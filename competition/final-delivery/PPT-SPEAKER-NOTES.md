## P1 封面｜校园智序·小序（约 30 秒）

- **画面重点**：深色封面 + 品牌 Logo；右侧超大"序"字水印。
- **点击节奏（4 组）**：①主标题"校园智序·小序" → ②副标题"面向学生、教师与教学管理者的…" → ③一句话能力 + 分隔线 → ④品牌主张"让教学时空，被理解、被安排。"
- **讲稿**：
  各位评委好。这是"校园智序·小序"——面向学生、教师与教学管理者的校园教学时空智能协同系统。它想解决的事情很简单：用一句自然语言，统一完成课表查询、空间查找、多人协同、调课核验和教学运行分析。我们的主张就一句话——让教学时空，被理解、被安排。
- **提示**：开场先站定 2 秒再开口；说到品牌主张时目光扫全场，然后翻页。

## P2 它从哪里来｜1500+（约 35 秒）

- **画面重点**：左侧"1500+ / 底层课表服务累计用户"+ 五个真实问题；右侧课程/教师/班级/教室/时间 → 教学安排关系图。
- **点击节奏（6 组）**：①1500+ → ②"查到课表，只是第一步" → ③五个问题逐条 → ④五个关系节点 → ⑤中心"教学安排" → ⑥底部结论"真实需求从'查得到'，长成'算得清、调得动、看得全'"。
- **讲稿**：
  先说它从哪里来。这不是一个从概念出发的作品——底层课表服务已经真实投入使用，累计用户 1500+。但在真实使用里，"查到课表"只是第一步。用户真正在问的是：谁有空？哪里有空？会不会赶不及？能不能调？哪里最忙？这五个问题，把课程、教师、班级、教室、时间连成了一张网——真实需求，让作品从"查得到"，长成"算得清、调得动、看得全"。
- **提示**：五个问题逐条点出，节奏放慢，这是全场的"问题锚点"。

## P3 谁在用它｜三类角色（约 30 秒）

- **画面重点**：学生 / 教师 / 教学管理者三栏，各配一句原话 + 能力清单。
- **点击节奏（5 组）**：①学生栏 → ②教师栏 → ③教学管理者栏 → ④两条分隔线 → ⑤底部"他们不需要学会教务系统的操作，只要把问题说出来。"
- **讲稿**：
  同一个系统，回答三类人每天最真实的问题。学生问：我今天有什么课？附近哪里有空教室？教师问：我们什么时候都空？能不能调整？教学管理者问：谁最忙？哪里可能有风险？他们不需要学会教务系统的操作——只要把问题说出来。
- **提示**：三栏逐一点亮，每栏停留 2–3 秒，别抢。

## P4 一句话怎样变成结果（约 40 秒）

- **画面重点**：左侾示例问题框；右侧"听懂问题 → 分给专家 → 算清事实 → 核验结论"四步。
- **点击节奏（8 组）**：①示例问题框 → ②"一句人话"说明 → ③步骤 01 听懂问题 → ④步骤 02 分给专家 → ⑤步骤 03 算清事实 → ⑥步骤 04 核验结论 → ⑦模型/CampusTools 分工一句话 → ⑧结果卡说明 + 底部标签"查得清 · 算得出 · 验得过 · 接得住"。
- **讲稿**：
  一句话是怎么变成结果的？比如这句："帮三位老师找共同空闲，再推荐一间不少于 120 座的教室。"用户只管说人话——不用填表单，也不用知道背后有哪些智能体。系统四步接力：听懂问题、分给专家、算清事实、核验结论。分工很清楚：模型负责听懂人话、组织协作；CampusTools 负责把动态校园事实算清楚。结果进入统一结果卡，还能继续追问"那看看他的课表""再查一下风险"。查得清、算得出、验得过、接得住。
- **提示**：四步逐格点出；底部十六字标签是本页记忆点，念一遍。

## P5 学生场景｜真实功能演示（约 35 秒）

- **画面重点**：左侧 4 个能力条目；右侧产品界面实拍截图（新导航：首页/角色与能力/已核验案例/真实体验）。
- **点击节奏（6 组）**：①查课表 → ②连续追问 → ③找空教室 → ④今日安排 → ⑤右侧界面截图 → ⑥底部"真实功能演示——没有包装的数字…"
- **讲稿**：
  学生场景，全部来自真实系统，可以在在线体验里现场验证。一句话查课表——班级、教师、课程、教室都可以查，例如"查看 2025 级计算机类 01 班第 1 周课表"；连续追问——"只看周三""那下午呢""这节课在哪"，上下文不丢、对象不换；找空教室——时间和空间一起回答，还可以继续筛；再加上今日安排。右边就是真实产品界面，没有包装，只有可以直接上手的能力。
- **提示**：手势指向右侧截图时停半秒，让评委看清导航。

## P6 教师案例一｜多人协同 3→63→7→A1-201（约 35 秒）

- **画面重点**：顶部数字链 3 → 63 → 7 → A1-201；下方协作链路实拍截图。
- **点击节奏（6 组）**：①"3 位教师" → ②"63 间可用教室" → ③"7 间不少于 120 座" → ④"A1-201 推荐教室" → ⑤下方截图 → ⑥底部"共同空闲 → 空间可用 → 容量过滤 → 给出推荐"。
- **讲稿**：
  教师案例一：一次完整的多人协同。第 1 周周四 1 到 4 节，三位老师要找共同空闲——系统先找到 63 间可用教室，再按"不少于 120 座"筛出 7 间，最后推荐 A1-201，正好 120 座。从共同空闲，到空间可用，到容量过滤，再到给出推荐——每一步都是工具算出来的，不是模型猜的。
- **提示**：数字链逐格点出，语气随数字递减收拢（63→7）制造"漏斗感"。

## P7 教师案例二｜风险发现 + 模拟调课（约 40 秒）

- **画面重点**：左侧 0 硬冲突 / 4 转场·20 分钟 / 模拟调课卡片；右侧风险检测与调课模拟两张实拍截图。
- **点击节奏（6 组）**：①"0 课表硬冲突" → ②"4 每周转场风险·最短间隔 20 分钟" → ③"课表没有打架 ≠ 人来得及赶到" → ④模拟调课卡（可行·有提醒·未写入） → ⑤风险检测截图 → ⑥调课模拟截图。
- **讲稿**：
  教师案例二，是风险发现加模拟调课的完整故事。教师 025，第 1 到 4 周：课表硬冲突是 0——但请注意，"课表没有打架"不等于"人来得及赶到"。系统算出每周 4 次教学空间转场风险，最短间隔只有 20 分钟。那"如果换到周四 7—8 节呢？"系统给出模拟结果：可以调，但有提醒——调整后教师连续 4 节连堂。关键看这三个字段：可行、有提醒、真实课表未写入。真实的课表，一个字都不会被改动。
- **提示**："0 不等于没问题"是本页反转点，说完停 1 秒再继续。

## P8 教学管理案例｜全局到个体（约 30 秒）

- **画面重点**：左侧三步下钻（教师 025 · 56 课次/112 课时 → 课表 → 风险）；右侧洞察页实拍截图。
- **点击节奏（4 组）**：①步骤 01 先找出最忙的人 → ②步骤 02 再看他的课表 → ③步骤 03 最后检查他的风险 → ④"答案层层接力，'他'始终是同一个人"+ 截图。
- **讲稿**：
  教学管理者的用法，是从全局到个体。第一步，未来四周谁的教学负载最高——教师 025，56 课次、112 课时；第二步，直接看他的课表——沿用同一个教师对象，不用重新输入；第三步，检查他的风险——0 硬冲突、每周 4 次转场。排名不是结论，而是发现问题的入口；答案层层接力，"他"始终是同一个人。
- **提示**：强调"同一个对象贯穿三步"，这是多轮接力的核心卖点。

- **讲稿**：

## P10 为什么相信它｜三层职责（约 30 秒）

- **画面重点**：三条横向层带（模型层 / 工具层 / 结果层），右下引言。
- **点击节奏（4 组）**：①层带 01 模型听懂人话 → ②层带 02 工具把事实算清 → ③层带 03 结果让人放心复核 → ④引言"模型可以理解，但不能自行编造校园事实。"
- **讲稿**：
  为什么相信它？因为三层各做自己最擅长的事：模型听懂人话、决定分工、解释结果；工具把课表、教室、时间、容量与风险算清楚——模型不能自行猜；结果让人放心复核——结论、提醒和证据一起进结果卡，失败时不会伪装成成功。一句话：模型可以理解，但不能自行编造校园事实。
- **提示**：引言是金句，念完直接翻页，不加评论。

### 高频追问预案（一句话答法）

- **"数据是真的吗？"**——演示数据为匿名版本化数据集，查询、计算与核验结果可稳定复现；1500+ 是底层真实课表服务的累计用户，页面口径已注明。
- **"模型会不会编？"**——CampusTools 是确定性工具层，模型不直接查库也不猜事实；结果卡带核验依据，失败时保守返回。
- **"调课会不会动真实数据？"**——模拟核验返回"可行 + 提醒 + 未写入"，mutatedData=false，真实课表零改动。
- **"为什么主协调不直接调工具？"**——职责边界：主协调只做理解/分工/汇总，工具调用由专业角色执行，所有结果统一解释，避免越权与结果不可追溯。
