## P1 封面｜校园智序·小序（约 30 秒）

- **画面重点**：深色封面 + 品牌 Logo；右侧超大“序”字水印。
- **点击节奏（4 组）**：①主标题"校园智序·小序" → ②副标题"面向学生、教师与教学管理者的…" → ③一句话能力 + 分隔线 → ④品牌主张"让教学时空，被理解、被安排。"
- **讲稿**：
  各位评委好。这是“校园智序·小序”——面向学生、教师与教学管理者的校园教学时空资源智能体。学生查课与找空间，教师协同与调课，管理者看全局与查风险。它不是万能校园助手，而是专门把课程、人员、时间、空间和规则组织起来。我们的主张就一句话——让教学时空，被理解、被安排。
- **提示**：开场先站定 2 秒再开口；说到品牌主张时目光扫全场，然后翻页。

## P2 它从哪里来｜1500+（约 35 秒）

- **画面重点**：左侧"1500+ / 底层课表服务累计用户"+ 五个真实问题；右侧课程/教师/班级/教室/时间 → 教学安排关系图。
- **点击节奏（6 组）**：①1500+ → ②"查到课表，只是第一步" → ③五个问题逐条 → ④五个关系节点 → ⑤中心"教学安排" → ⑥底部结论"真实需求从'查得到'，长成'算得清、调得动、看得全'"。
- **讲稿**：
  先说它从哪里来。这不是一个从概念出发的作品——底层校园课表服务累计服务用户达到 1500+；本次参赛作品是在这些真实需求基础上进一步扩展的校园教学时空协同智能体。但在真实使用里，"查到课表"只是第一步。用户真正在问的是：谁有空？哪里有空？会不会赶不及？能不能调？哪里最忙？这五个问题，把课程、教师、班级、教室、时间连成了一张网——真实需求，让作品从"查得到"，长成"算得清、调得动、看得全"。
- **提示**：五个问题逐条点出，节奏放慢，这是全场的"问题锚点"。

## P3 谁在用它｜三类角色（约 30 秒）

- **画面重点**：学生 / 教师 / 教学管理者三栏，各配一句原话 + 能力清单。
- **点击节奏（5 组）**：①学生栏 → ②教师栏 → ③教学管理者栏 → ④两条分隔线 → ⑤底部"他们不需要学会教务系统的操作，只要把问题说出来。"
- **讲稿**：
  同一个系统，回答三类人每天最真实的问题。学生问：我今天有什么课？附近哪里有空教室？教师问：我们什么时候都空？能不能调整？教学管理者问：谁最忙？哪里可能有风险？他们不需要学会教务系统的操作——只要把问题说出来。
- **提示**：三栏逐一点亮，每栏停留 2–3 秒，别抢。

## P4 一句话怎样变成结果（约 40 秒）

- **画面重点**：左侾示例问题框；右侧"听懂问题 → 分给专家 → 算清事实 → 核验结论"四步。
- **点击节奏（8 组）**：①示例问题框 → ②“一句人话”说明 → ③步骤 01 听懂问题 → ④步骤 02 分给专家 → ⑤步骤 03 算清事实 → ⑥步骤 04 核验结论 → ⑦模型/CampusTools 分工一句话 → ⑧4/13/14 与“查得清 · 算得出 · 验得过 · 接得住”。
- **讲稿**：
  一句话是怎么变成结果的？比如这句："帮三位老师找共同空闲，再推荐一间不少于 120 座的教室。"用户只管说人话——不用填表单，也不用知道背后有哪些智能体。系统四步接力：听懂问题、分给专家、算清事实、核验结论。分工很清楚：模型负责听懂人话、组织协作；CampusTools 负责把动态校园事实算清楚。结果进入统一结果卡，还能继续追问"那看看他的课表""再查一下风险"。查得清、算得出、验得过、接得住。
- **提示**：四步逐格点出；底部十六字标签是本页记忆点，念一遍。

## P5 学生场景｜从查课到找空间（约 35 秒）

- **画面重点**：左侧三句连续追问；右侧同一真实 ADP 会话的三轮结果截图。
- **点击节奏（5 组）**：①“查看 01 班第 1 周课表” → ②“只看周三” → ③“继续看周三下午，哪里有空教室” → ④“不用重填对象与周次” → ⑤右侧真实界面。
- **讲稿**：
  学生先说“查看 2025 级计算机类 01 班第 1 周课表”，接着只说“只看周三”，再问“继续看周三下午，哪里有空教室”。后两句话都没有重复班级和周次，小序仍然沿用刚才的对象与时间：第三轮实际调用空教室工具，给出主推荐与备选空间。右边就是这一组同会话、真实 ADP 返回的三轮证据。这里用“继续看周三下午”是跨日实测后的自然消歧，不是补填班级或周次。
- **提示**：三句话要像真实对话一样逐句说，不要讲成能力清单。

## P6 教师案例一｜多人协同 3→63→7→A1-201（约 35 秒）

- **画面重点**：顶部数字链 3 → 63 → 7 → A1-201；下方协作链路实拍截图。
- **点击节奏（6 组）**：①"3 位教师" → ②"63 间可用教室" → ③"7 间不少于 120 座" → ④"A1-201 推荐教室" → ⑤下方截图 → ⑥底部"共同空闲 → 空间可用 → 容量过滤 → 给出推荐"。
- **讲稿**：
  教师案例一：一次完整的多人协同。第 1 周周四 1 到 4 节，三位老师要找共同空闲——系统先找到 63 间可用教室，再按"不少于 120 座"筛出 7 间，最后推荐 A1-201，正好 120 座。从共同空闲，到空间可用，到容量过滤，再到给出推荐——每一步都是工具算出来的，不是模型猜的。
- **提示**：数字链逐格点出，语气随数字递减收拢（63→7）制造"漏斗感"。

## P7 教师案例二｜风险发现 + 模拟调课（约 40 秒）

- **画面重点**：左侧只保留 0 硬冲突 / 4 次转场·20 分钟 / 可行·有提醒·未写入三个锚点；右侧是两张实拍截图。
- **点击节奏（5 组）**：①"0 硬冲突" → ②"4 次转场 / 周·最短间隔 20 分钟" → ③"可行·有提醒·未写入" → ④风险检测截图 → ⑤调课模拟截图。
- **讲稿**：
  教师案例二，是风险发现加模拟调课的完整故事。教师 025，第 1 到 4 周：课表硬冲突是 0——但请注意，"课表没有打架"不等于"人来得及赶到"。系统算出每周 4 次教学空间转场风险，最短间隔只有 20 分钟。那"如果换到周四 7—8 节呢？"系统给出模拟结果：可以调，但有提醒——调整后教师连续 4 节连堂。关键看这三个字段：可行、有提醒、真实课表未写入。真实的课表，一个字都不会被改动。
- **提示**："0 不等于没问题"是本页反转点，说完停 1 秒再继续。

## P8 教学管理案例｜全局到个体（约 30 秒）

- **画面重点**：左侧三步下钻（教师 025 · 56 课次/112 课时 → 课表 → 风险）；右侧洞察页实拍截图。
- **点击节奏（4 组）**：①步骤 01 先找出最忙的人 → ②步骤 02 再看他的课表 → ③步骤 03 最后检查他的风险 → ④"答案层层接力，'他'始终是同一个人"+ 截图。
- **讲稿**：
  教学管理者的用法，是从全局到个体。第一步，未来四周谁的教学负载最高——教师 025，56 课次、112 课时；第二步，直接看他的课表——沿用同一个教师对象，不用重新输入；第三步，检查他的风险——0 硬冲突、每周 4 次转场。排名不是结论，而是发现问题的入口；答案层层接力，"他"始终是同一个人。
- **提示**：强调"同一个对象贯穿三步"，这是多轮接力的核心卖点。

## P9 背后怎么做到｜技术此时才出场（约 40 秒）

- **画面重点**：中间主协调椭圆 + 三个专业角色 + 右侧 CampusTools 四组工具带 + 底部 4/13/14 数字。
- **点击节奏（6 组）**：①"小序·主协调" → ②课程空间 → ③风险规划 → ④校园洞察 → ⑤CampusTools 工具区 → ⑥底部"4 智能体 · 13 项工具 · 14 绑定关系"。
- **讲稿**：
  到这里，才说技术。中间是小序·主协调——理解、分工、汇总；周围三个专业角色：课程空间，查课表、找教室、算共同空闲；风险规划，查冲突、识别转场、模拟调课；校园洞察，看负载、找第一、继续下钻。特别注意：主协调不直接调用 CampusTools——13 个面向智能体的确定性工具分四组，由专业角色使用，所有结果回到主协调统一解释。4 个智能体、13 项工具、14 组绑定关系，各管各的边界。
- **提示**："主协调不直接调工具"是架构纪律，务必点出（评委常追问）。

## P10 技术创新｜让任务接得住，让结果核得清（约 35 秒）

- **画面重点**：三条横向层带（多角色接力 / 事实单独核验 / 追问不用重来），底部可信边界。
- **点击节奏（4 组）**：①多角色接力 → ②事实单独核验 → ③追问不用重来 → ④“模型可以理解，但不能自行编造校园事实”。
- **讲稿**：
  这里的技术创新，不是多加一个模型，而是让任务接得住、让结果核得清。第一，多角色接力：主协调听懂目标，专业智能体各自处理课表、风险与洞察。第二，事实单独核验：课表、教室、容量和风险都由 CampusTools 计算。第三，追问不用重来：从“谁最忙”，到“看他的课表”，再到“查他的风险”，同一个对象持续传递。边界始终不变：模型可以理解，但不能自行编造校园事实。
- **提示**：第三点用“谁最忙 → 他的课表 → 他的风险”说清上下文价值。

## P11 真实落地与下一步（约 30 秒）

- **画面重点**：左侧 1500+ + 价值清单；右侧在线体验首页；底部四阶段路线。
- **点击节奏（8 组）**：①1500+ → ②升级说明 → ③五条价值 → ④右侧截图 → ⑤学生高频服务 → ⑥教师协同推荐 → ⑦教学管理预警 → ⑧教学时空治理。
- **讲稿**：
  最后说落地。1500+ 指的是底层校园课表服务累计服务用户，不等同于所有参赛智能体能力已有同样规模。本次作品是在真实需求基础上的升级：第一阶段是学生高频课表服务，第二阶段是教师协同与资源推荐，第三阶段是教学管理风险预警，第四阶段才走向教学时空数字化治理。价值很朴素：减少信息差和重复核对，降低协调成本，提前发现风险，让决策有事实依据。
- **提示**：主动声明"只呈现已发生的真实使用，不虚构活跃度、满意度或增长率"（页面副标题已写明，可指着说）。

### 高频追问预案（一句话答法）

- **"数据是真的吗？"**——演示数据为匿名版本化数据集，查询、计算与核验结果可稳定复现；1500+ 是底层真实课表服务的累计用户，页面口径已注明。
- **"模型会不会编？"**——CampusTools 是确定性工具层，模型不直接查库也不猜事实；结果卡带核验依据，失败时保守返回。
- **"调课会不会动真实数据？"**——模拟核验返回"可行 + 提醒 + 未写入"，mutatedData=false，真实课表零改动。
- **"为什么主协调不直接调工具？"**——职责边界：主协调只做理解/分工/汇总，工具调用由专业角色执行，所有结果统一解释，避免越权与结果不可追溯。
