# 《校园智序·小序》最终 4:45 视频脚本

> 成片锁定时长：**04:45**。叙事主线：真实问题 → 自然语言任务 → Multi-Agent 理解与分工 → CampusTools 确定性核验 → 可核查 Widget → 辅助决策。

## 0:00–0:15｜强 Hook

- 画面：黑场一拍后切入风险场景，大字先出现“冲突 0”，随后“赶场 4”从侧面滑入。
- 旁白：课表没有冲突，不代表教学安排没有风险。同一位教师的课程冲突为零，却每周有四次只有二十分钟的跨校区赶场。
- 屏幕字：`0 冲突 ≠ 0 风险`

## 0:15–0:35｜真实场景与落地

- 画面：真实教学任务关键词缓慢浮现；Judge Portal 首页由远及近。
- 旁白：校园教学安排同时跨越时间、空间、人群和规则。前期产品形态已在真实校园环境落地运行，累计服务用户一千以上。比赛作品由真实使用反馈继续生长，但对外只保留完全匿名的落地事实。
- 屏幕字：`真实校园环境｜累计服务用户 1000+｜完全匿名`

## 0:35–0:55｜系统架构

- 画面：4173 Architecture 场景，Main、Schedule、Risk、Insight 与 CampusTools 连线依次点亮。
- 旁白：校园智序·小序把复杂任务收敛为一句话。四个 Agent 负责理解、分工与解释，十三个 CampusTools 负责计算动态校园事实。主协调不直接调用工具，任务沿 Main、领域 Agent、Main 的路径完成闭环。共享的学期与教学周上下文形成唯一入口，十四个绑定全部落在三个领域角色上；没有子角色之间的转发，也没有第二套事实清单。
- 屏幕字：`4 Agent × 13 CampusTools × 14 bindings`

## 0:55–1:30｜Hero 1：教学风险发现

- 画面：用户输入“帮我看看教师025未来四周怎么上课”，切到教师周课表与跨校区连线。
- 旁白：用户只需问，帮我看看教师025未来四周的教学风险。风险 Agent 调用确定性工具，逐周读取十四个课次，分别检查时间重叠、校区变化与相邻课次间隔。结果不是一句模糊提醒，而是四周完全一致的可核验结论：每周冲突零次，跨校区赶场四次，最短转场间隔二十分钟。
- 屏幕字：`第1–4周｜14课次/周｜冲突0｜赶场4`

## 1:30–2:05｜Hero 2：多人协同规划

- 画面：三位匿名教师的空闲矩阵合并，候选教室由 63 收束到 7，A1-201 放大。
- 旁白：再看多人协同规划。三位教师要在第一周周四上午找到共同空闲，还要求教室至少一百二十座。系统先求三张课表的空闲交集，再联合筛选时间、容量与教室可用性。全校六十三间可用教室被收束为七个达标候选，最终推荐一百二十座的 A1-201，并保留候选数量与排名依据。
- 屏幕字：`3 位教师 → 63 → 7 → A1-201`

## 2:05–2:45｜Hero 3：What-if 模拟调课

- 画面：课程从周一5–6节拖向周四7–8节；六项约束依次出现 PASS；提醒以琥珀色保留。
- 旁白：调课更需要先核验、后决定。把一门课从第一周周一五到六节模拟移动到周四七到八节，系统逐项验证板块时间、教师时间、班级时间、教室占用、容量和功能属性。核心约束全部通过，所以 feasible 等于 true；同时，连续四节可能带来负荷，warning 仍然成立。整个过程只在内存候选上计算，mutatedData 等于 false，不写入真实数据。
- 屏幕字：`feasible=true + warning｜mutatedData=false`

## 2:45–3:20｜Hero 4：全局教学洞察

- 画面：未来四周负载榜从全局缩放到 Top1 教师025，再下钻风险卡。
- 旁白：全局洞察不止给出一个排行榜。未来四周负载汇总定位到第一名教师025，共五十六课次、一百一十二课时，连续四周每周十四课次。排名只负责定位对象；系统随后重新调用风险工具下钻核验，确认冲突为零、赶场为四，让宏观洞察最终落到可以处理的具体问题。
- 屏幕字：`Top1｜56课次｜112课时｜风险再核验`

## 3:20–4:05｜真实腾讯 ADP 操作

- 画面：必须使用真实控制台录屏。镜头完整保留用户输入、Main 调度、领域 Agent、CampusTools 调用与最终 Widget；不得以预制动画替代。
- 旁白：下面是一次真实的腾讯 ADP 操作。用户在对话框输入多人协同任务，主协调 Agent 识别目标和必要约束，把任务交给课程空间 Agent。领域 Agent 调用 CampusTools，工具从当前匿名数据版本计算共同空闲、教室占用和容量筛选。中间状态来自真实执行事件，不伪造思考或工具调用。结果返回主协调后，被组织成统一 Widget：一句结论、关键数字、推荐空间和 Evidence 同时出现。评审可以沿证据链复查输入、工具、数据版本与候选收束过程。
- 屏幕字：`真实输入 → Main → Child → CampusTools → Widget`

## 4:05–4:30｜为什么可信

- 画面：Verified、Evidence、fail-closed 四层依次点亮。
- 旁白：这套系统把理解能力与事实权威明确分开。生成模型负责理解任务、组织协作和解释结果；CampusTools 负责动态校园事实。统一结果卡与文本共享同一事实来源，关键结论都携带 Verified 与 Evidence。这意味着评审看到的数字，不是模型记忆里的答案，而是当前数据版本、明确输入和确定性算法共同产生的公开投影。遇到无结果、歧义或数据损坏，系统明确停止，不补全、不猜测，也不把降级包装成成功。
- 屏幕字：`Deterministic｜Verified｜Evidence｜fail-closed`

## 4:30–4:45｜品牌收束

- 画面：Logo 与品牌句定格，留出二维码和最终公开体验地址位置。
- 旁白：校园智序·小序，让教学时空，被理解、被核验、被安排。让复杂的校园教学安排，简单到一句话就能问。
- 屏幕字：`校园智序·小序`

- 画面统一 warm white、coral/red、rose/peach/淡 lavender 的 Iced Jelly / Liquid Glass 风格。
- 字幕使用 `SUBTITLES.srt`，时间轴已锁定为 04:45；音乐只做低频氛围，不遮挡中文口播。
