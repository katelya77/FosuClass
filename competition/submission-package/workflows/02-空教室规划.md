# 02-空教室规划

> 这是 ADP 手工搭建契约，不会自动覆盖平台中已经创建的开始输入。动态事实只来自 CampusTools。

## 1. 触发描述

用户要在指定校区、日期和节次寻找空闲教室；不处理某教室占用课表、两对象冲突或个人计划。

## 2. 最小节点（11 个）

```text
1. 开始
2. 参数提取
3. 必填判断
4. 缺参追问
5. 日期解析 → get_academic_context
6. 日期结果判断
7. 空教室查询 → find_available_classrooms
8. 结果契约判断
9. 工具/核验失败
10. 空结果或教室卡
11. 结束
```

## 3. 业务参数契约

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `campus` | string | 是 | 校区A|校区B；由 find_available_classrooms 校验 |
| `date_text` | string | 否 | 与 week+weekday 二选一 |
| `week` | number | 否 | 与 date_text 二选一 |
| `weekday` | number | 否 | 使用 week 时必填 |
| `start_period` | number | 是 | 1-10 |
| `end_period` | number | 否 | 与 consecutive_periods 二选一 |
| `consecutive_periods` | number | 否 | 与 end_period 二选一 |
| `building` | string | 否 | 由工具校验 |
| `capacity` | number | 否 | 最低容量，由工具校验 |

必填条件：`campus`、`date_text|week+weekday`、`start_period`、`end_period|consecutive_periods`。

时间策略：空教室必须有明确日期或教学周+星期；不把‘现在’猜成节次，无法确定时追问。

```text
只输出 JSON：
{"campus":"","date_text":"","week":null,"weekday":null,"start_period":null,"end_period":null,"consecutive_periods":null,"building":"","capacity":null,"inherited":false}

```

## 8. 分支契约

- 缺校区/时间/节次 → clarify
- 日期解析失败或学期外 → tool_error
- ENTITY_NOT_FOUND/INVALID_PARAM → tool_error（显示工具原始错误码，不由模型改写事实）
- success=true 且 items=[] → result(empty reply + 放宽建议)
- success=true 且 verified=true → result(classroom widget)

- 任何工具失败、版本不一致或 verified=false 都进入失败回复；生成模型不得补造课程、教室、冲突或计划事实。

## 9. 调试样例

1. 校区A明天下午有哪些连续两节空闲的教室
2. 周五晚上校区B有空教室吗
3. 校区A第3周周一上午的空教室
4. 找个能坐60人的空教室
5. 校区B明天下午连续三节的
6. （上文校区A后）那校区B呢
7. 现在哪里可以自习
8. 有空教室吗
9. 校区C明天的空教室
10. 校区A第25周的空教室
11. 校区A明天下午容量500的教室
12. 校区A明天全天哪些教室一直空着

## 10. 多轮上下文

只继承最近一次已确认且仍属于同一任务的字段；用户明确新值时覆盖，切换任务时清空无关字段。
