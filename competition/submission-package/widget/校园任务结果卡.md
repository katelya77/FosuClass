# Widget：校园任务结果卡

> 通用结果卡片设计稿，接入工作流 01（课表）与 02（空教室）起步，03/04 复用同构结构。

## 1. 设计目标

- 结果可快速扫读：3 秒内找到「有没有课/哪间教室」
- 可信可视：数据版本与核验状态固定在卡片上
- 可继续操作：每张卡带下一步按钮，把回答变成任务链
- 移动端优先，简洁现代，无 AI 生成感，零真实身份

## 2. 卡片通用骨架

```
┌─────────────────────────────┐
│ [cardType 图标] 标题          │
│ 副标题：数据版本 · 已核验 · 统计 │
├─────────────────────────────┤
│ 内容区（按 cardType 不同）      │
├─────────────────────────────┤
│ [下一步按钮1] [按钮2] [按钮3]   │
└─────────────────────────────┘
```

固定元素：
- **核验徽标**：`已核验 · competition-demo-v1`（绿色对勾图标 + 版本号）
- **时间条件条**：本次查询的 week/weekday/节次，让用户核对理解是否正确
- **下一步按钮**：不超过 3 个，来自信封 actions 字段

## 3. 六种 cardType

### 3.1 schedule（课表卡）— 接入工作流 01
- 标题：{entity_name} · {时间描述}课表
- 列表行：`第X节 | 课程名 | 教室 | 校区 | 教师`
- 空时段折叠显示，不刷屏
- 按钮：「看明天」「看整周」「查空教室」

### 3.2 classroom（空教室卡）— 接入工作流 02
- 标题：{校区} · {时间描述}空教室
- 副标题追加「共 N 间」
- 列表行：`教室号 | 楼栋 | 容量 | 空闲节次`
- 按钮：「换校区」「放宽为单节」「看明天」

### 3.3 conflict（冲突卡）— 接入工作流 03
- 标题：{A} × {B} 冲突比较
- 副标题：冲突 N 处 / 无冲突
- 冲突行：`第X周 周Y 第Z节 | A方课程 ⇄ B方课程`
- 跨校区奔波：橙色警告条单独高亮（rushWarnings）
- 按钮：「换个对象」「看A整周」「看B整周」

### 3.4 day_plan（今日计划卡）— 接入工作流 04
- 标题：{日期} 校园计划
- 时间轴：课程块（蓝）/ 自习建议块（绿）/ 提示块（灰）
- 跨校区提醒置顶黄色条
- 按钮：「查空教室」「看明天」「看整周」

### 3.5 error（错误卡）
- 标题：这次没有查成功
- 内容：人话版错误说明（不暴露内部码细节）+ 建议动作
- 按钮：「重试」「换个条件」

### 3.6 choice（歧义候选卡）
- 标题：找到多个匹配，选一个
- 候选行：`名称 | 所属学院/校区`（最多 5 个）
- 交互：点选后自动携带原条件继续查询

## 4. 视觉规范

- 圆角 12px，卡片间距 8px，主色 #2B6CB0（校园蓝），成功 #38A169，警告 #DD6B20，错误 #E53E3E
- 标题 16px/600，正文 14px，辅助 12px 灰色
- 单行信息不超 2 行，超出省略
- 核验徽标统一右上角或副标题内，弱化但可见
- 深色模式自适应（ADP 侧若支持）

## 5. 与工具信封的字段映射

| 卡片元素 | 信封字段 |
|---|---|
| 标题对象 | resolvedEntity |
| 版本徽标 | dataVersion |
| 列表内容 | items |
| 下一步按钮 | actions |
| 空结果说明 | evidence.note |
| 错误说明 | error.message（人话化后） |

## 6. ADP 落地方式

1. ADP Widget 编辑器创建「校园任务结果卡」，定义上述 6 种 cardType 的变量绑定。
2. 工作流 01/02 的输出节点选择该 Widget，映射信封字段。
3. 若 ADP Widget 能力不足（如不支持条件高亮），退化为「结构化文字 + 简化卡片」，并创建独立匿名 H5 演示端承载完整效果（见 widget/h5-demo 说明，保留 ADP 工作流为智能体核心）。

## 7. 验收标准

- 每条查询结果 3 秒内可读懂核心信息
- 所有卡片必现 dataVersion 与核验状态
- 歧义场景必须出 choice 卡而不是文字罗列
- 失败场景必须出 error 卡且不含内部细节
