# 工作流 03：课程冲突比较

> 蓝图用途：在 ADP 工作流编辑器中照此搭建。

## 1. 触发描述

用户想比较两个对象（班级/教师/课程）在同一时间范围内的课程冲突，用于协调会议、合班上课、双选判断等。典型说法：
- 「比较2025级A班与B班周五下午的课程冲突」
- 「教师001和教师002周三都有课吗」
- 「A班和C班这周哪天下午都有空」
- 「我想同时听两门课，时间冲不冲突」

## 2. 节点结构

```
开始
 → ① 参数提取（大模型节点，输出 JSON，两个对象）
 → ② 条件判断：两个对象是否齐全
     ├─ 缺一个 → ③a 追问缺失对象 → 结束
     └─ 齐全 → ④ 双实体归一化（工具节点：resolve_entity ×2）
         ├─ 任一 NOT_FOUND / AMBIGUOUS → ④a 对应分支话术 → 结束
         └─ 都命中 → ⑤ 时间换算（默认全学期每周重叠分析；指定天则定位）
             → ⑥ 调用 compare_schedules（工具节点）
                 ├─ 失败 → ⑦a 失败话术 → 结束
                 ├─ 无冲突 → ⑦b 明确无冲突 + 可用于什么 → 结束
                 └─ 有冲突 → ⑧ 结果核验（含 rushWarnings 跨校区提醒）
                     → ⑨ Widget conflict 卡 + 结构化文字 → 结束
```

## 3. 参数规范

| 参数 | 必填 | 说明 |
|---|---|---|
| first_entity_type / first_entity_name | 是 | 比较对象一 |
| second_entity_type / second_entity_name | 是 | 比较对象二 |
| date_range 或 week+weekday | 否 | 默认全学期重叠 |
| period_scope | 否 | 「周五下午」→ weekday=5 + 5-8节 |

## 4. 参数提取提示词

```
你是课程冲突比较参数提取器。只输出 JSON：
{
  "first_entity_type": "class|teacher|course",
  "first_entity_name": "归一化名",
  "second_entity_type": "class|teacher|course",
  "second_entity_name": "归一化名",
  "date_text": "原文时间或空",
  "week": "或空", "weekday": "或空",
  "period_scope": "或空",
  "inherited": "true|false"
}
规则：
1. 「A班和B班」→ first=2025级A班，second=2025级B班（按出现顺序）。
2. 只说一个对象时另一个留空，不得编造。
3. 「都有空的时间段」→ 反向需求，标记 note="find_common_free"，仍走冲突比较再取反说明。
4. 只输出 JSON。
```

## 5. 分支话术

- 缺第二对象：「想和哪个对象比较？比如另一个班级或教师。」
- 无冲突：「{A}和{B}在{范围}没有课程冲突，可以安排共同事项。」
- 有冲突：展示冲突点列表（周次/星期/节次/双方课程），跨校区奔波单独高亮提醒。

## 6. 输出与 Widget

Widget cardType=conflict：
- 标题：{A} × {B} 冲突比较
- 副标题：数据版本 competition-demo-v1 · 已核验 · 冲突 N 处
- 冲突列表：周次/星期/节次/A方课程/B方课程
- 高亮：跨校区奔波警告（rushWarnings）
- 按钮：「换个对象比较」「看{A}整周」「看{B}整周」
