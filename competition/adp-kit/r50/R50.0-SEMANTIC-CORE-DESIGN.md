## 0. 总原则

- **禁止 Prompt Case Overfitting**：测试可用大量不同自然语言表达验证原则；业务实现代码禁止
  `if query === "看Top1课表"`、`text.includes("未来四周") → week=1..4` 这类针对测试字符串的硬编码。
- **确定性优先**：所有日期/周次/排名/排序由 deterministic 层校验与计算，LLM 只提供结构化 intent，不直接输出最终数字。
- **用户可见输出与内部协议严格分离**：用户回复只展示真实业务结果 + 必要解释 + "数据已核验"；内部
  rankContext/windowContext/temporalContext/sourceTool/queryId/dataHash/Agent 名称/工具名/raw JSON 一律不默认展示。
- **7 工具冻结**：已有 7 个 Agent Tool 的 URL/operationId/核心 request contract/成功 response semantics 只允许 backward-compatible 增强。

## 1. Temporal Semantic Core（统一确定性时间解析层）

### 1.1 目标

Agent 不再靠 Prompt 猜「未来第一周是不是第1教学周 / 当前日期是否学期内」。统一由 `temporal-core.js` 计算。

### 1.2 支持的 temporal intent（Agent 可输出结构化 intent；日期/周次由本层校验计算）

| intent.kind | 说明 | 示例输入（Agent 结构化） |
|---|---|---|
| `absolute` | 绝对日期 | `{kind:"absolute", date:"2026-09-03"}` |
| `relative_day` | 相对天 | `{kind:"relative_day", offset:0\|1\|2\|-1}`（今天/明天/后天/昨天） |
| `relative_weekday` | 周内星期 | `{kind:"relative_weekday", weekday:1..7, offset:0\|1\|-1}`（本周X/下周X/上周X） |
| `academic_week` | 第 N 教学周 | `{kind:"academic_week", week:1..20}` |
| `academic_week_weekday` | 第 N 周周 X | `{kind:"academic_week_weekday", week, weekday}` |
| `week_range` | 第 N..M 周 | `{kind:"week_range", weekStart, weekEnd}` |
| `future_weeks` | 未来/接下来 N 个教学周 | `{kind:"future_weeks", count:N}` |
| `recent_weeks` | 最近 N 个教学周 | `{kind:"recent_weeks", count:N}` |
| `next_week` / `prev_week` | 下一/上一教学周 | `{kind:"next_week"}` / `{kind:"prev_week"}` |
| `current` | 当前日期（默认） | `{kind:"current"}` |

### 1.3 「未来/接下来 N 个教学周」唯一契约定义

- 从 `referenceDate` 所在有效教学周开始；若 `referenceDate` 不在学期教学周（开学前/学期后/假期），则从**之后第一个有效教学周**开始。
- 「未来第一个教学周」= 该窗口第 1 个有效教学周。
- 例：referenceDate=2026-08-18（开学前）→ 第一个有效教学周 = 1 → 未来4个教学周 = 1..4。
- 例：referenceDate=2026-10-05（第6教学周内）→ 未来4个教学周 = 6..9。
- `resolvedWeekStart` = 起始有效教学周；`resolvedWeekEnd` = min(起始+count-1, totalWeeks)；若超界按 totalWeeks 截断并保留 `note`。

### 1.4 「最近 N 个教学周」唯一契约定义

- `referenceDate` 在教学周内 → `[week-N+1, week]`（含当前周）。
- `referenceDate` 在学期后 → `[totalWeeks-N+1, totalWeeks]`。
- `referenceDate` 在开学前 → 无已开展教学周，返回 `resolvedWeekStart/End = null` + `resolutionKind="pre_semester"`，由上层澄清或退化为「即将开始的第1周」。
- `referenceDate` 在学期内假期（无课周仍属教学周序）→ 按所在教学周序处理。

### 1.5 temporalContext 输出契约

```ts
{
  referenceDate: string,          // YYYY-MM-DD 基准（默认 Asia/Shanghai 今天，可 baseDate 覆盖）
  semesterId: string,
  inSemester: boolean,            // referenceDate 是否在学期教学周内
  currentAcademicWeek: number|null,
  resolvedDate: string|null,      // 单日期语义才填充
  resolvedWeek: number|null,      // 单周语义
  resolvedWeekStart: number|null, // 窗口起（含）
  resolvedWeekEnd: number|null,   // 窗口止（含）
  resolutionKind: string,         // absolute|relative_day|...|pre_semester|post_semester|none
  note?: string                   // 截断/退化说明（非用户默认展示）
}
```

- 不得把 temporalContext 原始 JSON 默认展示给用户。

## 2. Generic Context Model（统一内部 Context）

```
context = {
  intentContext,      // 本轮结构化意图（turnType/intent kind + 业务域）
  entityContext,      // 当前明确/继承实体（activeEntity + candidates）
  temporalContext,    // 由 Temporal Semantic Core 解析
  rankingContext,     // 仅当本轮/历史真正产生排序结果时存在
  comparisonContext,  // 仅显式比较任务需要
  taskContext,        // 复合请求未完成子任务跟踪
}
```

- 跨域继承原则：只继承当前任务完成所必需的信息；domain-local 临时状态不得污染不相关新任务。
- 用户当前明确表达永远覆盖继承值。
- 不新增针对单一 Case 的特殊字段（现有字段保持兼容）。

## 3. Ranking Semantic Core（通用排名机制）

### 3.1 metric vs position

- **metric semantics**：「最高/最低/最忙/最空闲/利用率最高」= 指标查询（返回排序后的 metric 列表）。
- **position semantics**：Top1/第一名/排第一/TopN = 有序列表的稳定位置；**位置解析不因 metric tie 失效**。
- 若业务指标并列：必须保留 tie metadata，同时仍具 deterministic position（稳定 tie-break）。

### 3.2 RankingResult 结构（兼容旧字段）

```ts
{
  rank: number,            // 1-based 位置（position 语义）
  metricRank: number|null, // 业务指标并列组内的排序（与 rank 可能不同）
  tiedWithPrevious: boolean,
  tieGroupId: string|null, // 并列组标识（如 "tie:27:54"）
  tieGroupSize: number,    // 该并列组实体数
  entity: { id, name, type },
  metrics: Record<string, number|string>,  // 该实体本轮指标
}
```

- 复用范围：teacher load / room utilization / campus load / building utilization。

## 4. 13 Agent-facing CampusTools 清单与契约

### 4.1 既有 7 个（冻结，不改 URL/operationId/核心契约）

1. campus_schedule_query → query_schedule
2. campus_schedule_range_query → query_schedule_range
3. campus_classroom_search → find_available_classrooms
4. campus_risk_check → compare_schedules（self/compare）
5. campus_day_plan → generate_day_plan
6. campus_overview → get_campus_teaching_overview
7. campus_teacher_load_query → query_teacher_load

### 4.2 新增 6 个（R50.0）

8. `campus_entity_search` → 底层 `query_entity_search`：list/exact/normalized/prefix/substring/fuzzy 解析，确定排序，禁止 LLM 编造实体。
   - 输入：entityType? keyword? campus? college? limit?
9. `campus_academic_context` → 底层 `get_academic_context` 增强：封装 Temporal Semantic Core，暴露 temporalContext。
10. `campus_common_free_time_query` → 底层 `query_common_free_time`：2~6 个教师/班级共同空闲窗口。
    - 输入：entities[]、week 或 temporal range、weekday? periodStart? periodEnd? minConsecutivePeriods?
11. `campus_room_utilization_query` → 底层 `query_room_utilization`：weekStart/weekEnd、campus/building/roomType、topN、sort=highest|lowest。
    - 返回 occupiedPeriodUnits/availablePeriodUnits/utilizationRate/lessonOccurrences；room/building/campus 为正式 ranking entity。
12. `campus_reschedule_feasibility` → 底层 `check_reschedule_feasibility`：What-if 模拟（绝不修改原数据）。
    - 输入：source lesson、target week/day/period/room；检查 teacher/class/room conflict、capacity、feature、adjacent、cross-campus rush、continuous load。
13. `campus_group_plan` → 底层 `plan_group`：共同空闲 + 空教室 + 容量 + 可选设备需求 → 确定性 ranked 候选；不得 LLM 拼装虚构房间。

## 5. Anonymous Campus Dataset V3

### 5.1 目标规模（seeded deterministic，byte-stable）

- campuses: 4；colleges: 6~8；classes: 24~32；teachers: 36~48；courses: 60~80；rooms: 72~96；lesson definitions: 160~220；demoUsers: 3~5；20 教学周。
- 第一至第四周高数据密度（排名/风险/空间利用率/共同空闲/调课模拟/群体规划均有丰富正负样例）。

### 5.2 实体命名（匿名但非 Demo 感）

- 学院：工程与计算类 / 生命与环境类 / 人文与设计类 / 经管与公共类 / 基础科学类 / 教育与体育类（通用虚构学科类别，不对应特定真实大学）。
- 班级：2025级计算机类01班 / 2025级生命科学类01班 / 2024级机械类01班 / 2025级中文类01班 / 2024级经管类02班 等（synthetic 专业簇）。
- 教师：T001..T048 / 教师001..教师048（禁止真人姓名）。
- 禁止真实学校/学院/教师/班级/个人课表可识别数据；不使用 佛山大学/华南理工大学/韩山师范学院 等任何现实校名。

### 5.3 课程体系（覆盖公共基础/工程/生命科学/人文/经管/教育/实践）

- 公共基础：大学英语、高等数学、线性代数、大学物理、大学体育、学术写作、信息素养
- 工程：程序设计、数据结构、电路基础、工程制图、机械基础、自动控制
- 生命科学：普通生物学、生物化学、遗传学基础、动物生理学、生态学基础、实验技能
- 人文：现代汉语、中国文学、传播基础、学术阅读
- 经管：管理学、经济学基础、统计学、市场分析
- 教育：教育学、心理学基础、课程设计
- 实践：课程实验、创新训练、专业见习、项目实践、毕业设计指导、研讨课

### 5.4 周次表达多样（必须真实生成）

1-16周 / 1-8周 / 9-16周 / 单周 / 双周 / 1-16周(单) / 2-16周(双) / 2,4,6,8周 / 1-4,7-10周 / 短期实践周 / 周末课程 / 晚间课程 / 连续3/4节实验 / 跨周不规则课程。

### 5.5 教室与资源模型增强（向后兼容）

- room 增加：capacity / type / features[]（projector/computer lab/wet_lab/smart_board/movable_seats/recording/language_lab/studio/seminar）。
- course 增加：requiredFeatures[] / expectedSize / courseType。

### 5.6 校区与建筑 + campus travel matrix

- 校区A/B/C/D；建筑：综合教学楼/基础实验楼/工程实践楼/人文教学楼/创新中心/公共教学楼。
- 新增确定性 `campusTravelMatrix`（分钟级，A→B→C→D 等），用于跨校区赶场与 reschedule feasibility；非现实地图。

### 5.7 designed scenarios（人为设计，非全随机）

单教师同时段冲突 / 两班冲突 / 教室冲突 / 20分钟跨校区赶场 / 足够时间跨校区非风险 / 连续4节 / 高负载教师 / 低负载教师 / 教室高利用率 / 教室低利用率 / 多教师共同空闲 / 无共同空闲 / 60/100/150人容量筛选 / feature 不匹配 / 调课可行 / 调课教师冲突 / 调课教室冲突 / 调课容量不足 / group plan 多候选 / 无候选 / 周末空日 / 晚间课 / 单双周差异。

### 5.8 V2/V3 版本策略

- V2 保持 regression frozen（Golden/QA/Widget 样例锚定不变）。
