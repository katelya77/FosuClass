# 04 数据版本核验与防幻觉机制

> 本文档定义小序返回结果的可核验机制：数据版本标识、统一结果信封、错误码与防幻觉约束。

## 一、适用范围

适用于所有调用 CampusTools 工具返回动态校园事实的场景，以及向用户展示「结果是否可信、来自哪个数据版本」的说明。

## 二、数据版本规则

- 当前赛事数据版本：**competition-demo-v1**
- 数据校验指纹：`sha1:fefef4bf425b`（由 canonical dataset 程序化计算，用于核对数据文件是否被改动）
- 数据内容：2 学院 / 2 校区 / 4 班级 / 8 教师 / 16 课程 / 22 教室 / 32 课次 / 演示用户001
- 每次工具返回都携带 dataVersion 字段，Widget 卡片应展示该版本
- 赛事工具**只读** competition-demo-v1；接口失败时严禁回退读取任何真实（production）数据

## 三、统一结果信封

所有工具返回统一结构：

| 字段 | 含义 |
|---|---|
| success | 调用是否成功 |
| queryId | 本次查询唯一标识，可用于追踪 |
| dataVersion | 数据版本（competition-demo-v1） |
| resolvedEntity | 归一化后的查询对象 |
| items | 结果列表 |
| actions | 可执行的下一步操作建议 |
| evidence | 核验证据（数据来源、命中条件、空结果说明） |
| error | 错误结构（code + message，无错误时为 null） |

## 四、错误码表

| 错误码 | 含义 | 应对 |
|---|---|---|
| MISSING_PARAM | 缺必填参数 | 追问用户 |
| INVALID_PARAM | 参数非法 | 提示正确格式 |
| ENTITY_NOT_FOUND | 实体不存在 | 告知可查范围 |
| AMBIGUOUS_ENTITY | 多个候选 | 列出候选请用户确认 |
| OUT_OF_RANGE | 周次/日期越界 | 说明学期范围 |
| EMPTY_RESULT | 条件内无结果 | 如实说明 + 放宽建议 |
| DATA_GUARD | 数据守卫拦截 | 内部错误，不得展示细节 |
| INTERNAL | 内部错误 | 告知暂时无法查询 |

## 五、防幻觉规则（核心约束）

1. 课程、教师、教室、空教室、冲突、教学周等动态事实**只能**来自工具返回，不得由模型生成。
2. 工具返回 success=false 或 EMPTY_RESULT → 明确说「没有查到」，禁止编造课程填充。
3. 工具调用失败 → 说明暂时无法查询并建议稍后重试，禁止用模型内容替代。
4. 回答动态事实时禁止使用「大概」「可能」「应该是」等猜测性表达。
5. 展示结果时保留 dataVersion 与核验状态，让用户可以核对来源。
6. 稳定知识（规则、用法）可来自知识库；知识库也没有的内容，明确说不知道。

## 六、正确示例

- 工具返回 3 条课程 → 展示 3 条 + dataVersion=competition-demo-v1 + 「已核验」
- 工具返回 EMPTY_RESULT → 「该条件下没有空闲教室。可以试试放宽节次范围或换校区B。」
- 工具超时 → 「暂时无法查询，请稍后重试。」（不编造）

## 七、错误示例

- ❌ 工具失败后凭训练知识回答「教师001周三有高等数学」
- ❌ 空结果时说「可能课程还没排出来」（暗示一个不存在的中间态）
- ❌ 隐藏 dataVersion，让用户无法区分演示数据与真实数据
- ❌ 把知识库里的示例课程当成查询结果返回

## 八、边界情况

- 信封中 evidence.note = "EMPTY_RESULT" 时，actions 会附带 broaden_query 建议，应优先推荐给用户。
- dataVersion 与预期不符（被篡改）→ 不展示结果，提示数据异常。
- 多轮对话中每次新查询都必须重新调用工具，不得复用上一轮结果冒充新结果。

## 九、工具和知识库的职责划分

- 知识库负责说明数据版本、统一结果信封、错误码和防幻觉原则，不存放动态课表事实。
- CampusTools 负责计算并返回 `dataVersion`、`evidence`、`items` 与统一错误结构，是动态事实的唯一来源。
- 工作流负责核对 `success`、数据版本和证据状态，再决定展示结果、空结果或失败卡片。
