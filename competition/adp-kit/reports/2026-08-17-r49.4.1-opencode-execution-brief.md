## Prompt semantic requirements

### Main

Teacher-load rank context must be source-aware. A valid equivalent contract is:

```json
{
  "sourceTool": "campus_teacher_load_query",
  "sourceDomain": "teacher_load",
  "list": "teacherLoadTop",
  "rankingWindow": {"weekStart":1,"weekEnd":4},
  "selectedRank": 1,
  "entities": []
}
```

Do not hardcode all rankContext to `source="campus_overview"`.

### Insight

Authoritative split:

- `campus_teacher_load_query`: teacher load / teacher TopN / arbitrary weekStart..weekEnd / topN or campus filter changes.
- `campus_overview`: fixed-window campus-wide overview, campus resource pressure, overall scale, global risk/trend.

Remove contradictory rules saying all dynamic load numbers or all window changes must use `campus_overview`.

### Schedule

- multi-week `detailWindow` → `campus_schedule_range_query`;
- one week → fresh `campus_schedule_query`;
- explicit current-turn time overrides inherited window;
- no valid window → NEED_CLARIFICATION;
- never default to week=1.

### Risk

A rankContext can identify the entity but a multi-week ranking window is not a valid risk week. Without an explicit single week/date, return NEED_CLARIFICATION to Main and do not call `campus_risk_check`.
