## 1. 实际完成项

### 正式产品“佛课小表”

- 新增统一用户可见品牌配置 `miniprogram/config/assistantBrand.js`：小序、校园智序、校园智序 · 小序、校园任务助手及旧称兼容列表。
- 小程序助手入口、悬浮组件、助手页、设置、记忆面板、结果表达等用户可见名称迁移为“小序”。
- 服务端公开回复、项目知识、模拟 Provider、Response Composer、后台知识库等用户可见文案同步迁移。
- 保留 `packageXiaofu`、`xiaofu*` 文件/组件路径、存储键、数据库字段、协议字段和旧称识别别名，避免破坏旧缓存、旧会话和组件引用。
- 没有改变正式产品数据源和生产发布配置。

### 匿名赛事数据与知识工程

- 独立生成 `competition-demo-v1`，不是对真实数据做字符串替换。
- 数据包含 2 学院、2 校区、4 班级、8 教师、16 课程、22 教室、32 课次、20 周学期和 1 个匿名演示用户，可覆盖课表、空教室、冲突和日计划。
- 提供 JSON Schema、确定性生成器、校验器和数据哈希。
- 完成 7 份稳定知识 Markdown，均具备适用范围、规则、正反例、边界和工具/知识库职责划分。
- 完成 32 条标准问答；JSON 为权威源，脚本可检查/重建 CSV。
- 完成 80 条评测数据和 10 维评分规则，覆盖成功、缺参、多轮、空结果、工具失败和提示注入。

### CampusTools API 与 MCP

- Node.js 只读服务支持 Streamable HTTP MCP、SSE 兼容、REST、`tools/list`、`tools/call` 和健康检查。
- 六项工具：`resolve_entity`、`get_academic_context`、`query_schedule`、`find_available_classrooms`、`compare_schedules`、`generate_day_plan`。
- 统一响应含 `success/queryId/dataVersion/resolvedEntity/items/actions/evidence/error`。
- 包含 JSON Schema 输入、超时、限流、结构化日志、token/HMAC 鉴权、Dockerfile、OpenAPI 3.0 与自动化测试。
- 数据加载器只接受比赛数据，不存在 production 失败回退路径。
- 提供 CloudBase HTTP Function 可复现部署包装；生成副本由同步脚本从 MCP 权威实现和匿名数据构建，漂移会令测试失败。
- 独立比赛测试入口已部署，公网 health、未授权 401 和授权确定性查询 200 均已实测；函数只使用 `competition-demo-v1`。

### 工作流和结果层

- 四条工作流均有触发描述、结构化参数提示、14 节点公共结构、缺参/歧义/失败/空结果分支、工具映射、结果核验、Widget 输出和 10 条以上调试样例。
- `校园任务结果卡` 支持 schedule、classroom、conflict、day_plan、error、choice 六种卡型。
- 提供匿名移动端 H5 兜底和六种生成样例；ADP Widget 受限时可用于展示，但不能替代 ADP 工具链。

测试过程发现并修正：

1. 七份知识文档的统一章节命名不完整，导致 kit 结构校验失败；已逐份补齐并保留原有更丰富内容。
2. QA JSON 有 32 条、旧 CSV 有 36 条，存在来源漂移；已规定 JSON 为权威源并加入同步检查。
3. 后台知识库仍有两处“小佛助手”用户可见残留；已迁移并加强复制审计。
4. 旧资产清单哈希与后续审阅内容不一致；已新增 53 文件资产清单同步/校验，并让 `generate` 不再覆盖受审阅的知识、工作流和评测文件。
5. Widget 样例曾因随机 queryId 和 computedAt 每次产生不同哈希；已固定样例元数据，连续两次生成结果完全一致。
6. CloudBase 托管包装最初继承通用 MCP 服务的“无鉴权本地开发”默认值；审阅后改为赛事函数缺少 token 即拒绝启动，并在重新部署后完成 200/401/200 三路径验证。

## 5. 回滚路径

- 所有实现位于独立分支 `feat/campusflow-adp-integration`，通过 PR #49 与远端同步；尚未合并 main，没有触发生产部署。
- 独立比赛函数可通过停用网关/函数回滚，但停用会影响 ADP 测试，执行前应确认；token 可独立轮换，无需改代码。
- 比赛资产集中在 `competition/adp-kit/`，可单独移除而不影响正式数据链路，但移除前应先确认没有用户新增内容。
- 品牌迁移以 `assistantBrand.js` 为集中开关；如需回滚显示文案，应修改该配置及少量服务端展示文案，不能删除旧称兼容别名或改动 `xiaofu` 协议标识。
- ADP 侧在最终发布前保留现有版本；工作流和知识库删除、覆盖或发布/回滚均属于高风险动作，必须人工确认。

## 6. 最少人工步骤

在网页自动化无法选择本地文件或平台触发安全验证时，用户只需完成对应的文件选择、验证码/手机授权。当前主要人工阻点是给浏览器控制扩展开启“允许访问文件网址”，以便上传知识库、问答和评测文件；最终比赛提交版本发布前还需要用户一次总确认。其余 ADP 普通配置可继续由已登录网页端代理执行。
