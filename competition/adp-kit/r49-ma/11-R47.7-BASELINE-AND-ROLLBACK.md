# 11 — R47.7 Golden Baseline 与回滚

## 0. 定位

R47.7（`00-小序会话总控-R47.7-Graph-Context-Integrity`，平台侧 00 内嵌 01-05）从本轮起定义为：

1. **Golden Baseline** —— 多轮/多域正确行为的事实真值来源。
2. **Regression Baseline** —— 每次架构改动后回测对比，禁止事实倒退。
3. **Emergency Fallback** —— Multi-Agent 出现无法快速修复的回归时一键回滚对象。

**不删除、不覆盖、不退役** R47.7 与旧 01~05；本轮仓库工作不影响平台侧已导入基线。

## 1. 迁移前必须完成的基线存档

- [ ] 在腾讯 ADP 控制台导出 `00-小序会话总控-R47.7-Graph-Context-Integrity` 完整工作流 ZIP。
- [ ] 导出已绑定 Widget 的真实包（schedule/classroom/conflict/day-plan/campus-overview/choice/recovery）。
- [ ] 记录：AgentID / WorkflowID / WidgetID / PluginID 真实值到安全位置（不提交仓库）。
- [ ] 记录 R47.7 当前通过的应用层复验结果快照（13 case + R48 A~G）。
- [ ] 在仓库归档：`competition/adp-kit/r49-ma/reports/r47.7-baseline-snapshot.md`（快照结论 + 存档位置说明，不存真实 ID）。

## 2. Regression 对比协议

- 每次改动后：运行 `09-MULTI-AGENT-E2E-MATRIX.md` 的 A~H + 13 case + R48 A~G。
- 对比基准：R47.7 Golden Baseline 快照。
- 判定：任一动态事实字段不一致（课程、节次、地点、冲突、风险、负载数字）→ 视为事实倒退，阻断。
- 判定：任一 stale/self-risk/Top1/下一天硬性要求失败 → 阻断。

## 3. Emergency Fallback 触发条件

任一 P0 未解决且影响演示：
- self-risk 被要求第二对象；
- stale context 污染新任务（A校区空教室被旧 risk 卡住）；
- Top1 下钻伪造；
- day_plan 下一天进入恢复卡。

## 4. 回滚步骤（平台侧）

1. 在 ADP 控制台停用/下线 Multi-Agent 应用。
2. 重新启用 R47.7 应用实例（或恢复之前导出的 00+01-05 工作流 ZIP 重新导入）。
3. 恢复 R47.7 已绑定的 Widget 与角色指令/知识库（知识库本轮已修复为 v2，回滚时以基线快照为准）。
4. 用回归矩阵快速复验 R47.7 基线是否恢复。
5. 记录回滚原因与时间，供后续修复。
