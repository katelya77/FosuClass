# R50.2A Product E2E Matrix（能力族 · 人类 Console 验收）

> 依据：`docs/superpowers/specs/2026-08-19-r50.2-unified-native-widget-system-design.md` §4.3 与
> `docs/superpowers/plans/2026-08-19-r50.2a-interaction-semantics-prompt-hardening.md` Task 1/7。
> 本矩阵只定义**人类在 Tencent ADP Console 中执行的验收能力族**，不绑定六条字面问题句式
> （旧 D1~D6 不再作为「神圣字面集」）。确定性协议冒烟仍由 `r49-ma` 测试承载。

## 分层原则

- **Protocol Smoke（协议冒烟）**：可使用 fixture / 内部 ID（如 `sourceLessonId`）验证确定性 façade 行为；由 `test-r50-1-e2e-matrix.js` 等自动化测试承担，不属于本矩阵。
- **Product E2E（产品验收）**：使用自然用户目标与多轮连续性；冷启动用户不需要知道任何 `lesson-xxx` 内部 ID；本矩阵记录所需 Console 证据。

## 能力族总览

| 族 | 能力 | 目标意图族 | 期望子 Agent | 允许工具 | 禁止行为 | 所需 Console 证据 |
|---|---|---|---|---|---|---|
| P-BROWSE | 浏览/清单已知实体类别 | BROWSE_LIST | Schedule（实体发现） | campus_entity_search（bounded list） | 无必要澄清；追问「想要哪种清单」 | 一次「列出某类实体」请求直接得到有界清单，无澄清表单 |
| P-TEMPORAL | 相对教学周请求 | （时间解析） | Schedule（经 campus_academic_context） | campus_academic_context | 静默默认 week=1 | 一次「下周/当前周」类请求解析到正确教学周 |
| P-AVAILABLE | 纯共同空闲发现 | AVAILABILITY_DISCOVERY | Schedule | campus_common_free_time_query | 走成 group_plan 或虚构窗口 | 一次「这些实体什么时候都有空」→ common_free_time 结果 |
| P-PLAN | 安排/候选方案 | GROUP_PLANNING | Schedule | campus_group_plan | 仅因用户没提「教室」而退化为 common_free_time | 一次「安排会议给候选时段/方案」→ 实际调用 group_plan，含 ranked 候选 |
| P-RANK | 教师/教室排名 | （排名） | Insight | campus_teacher_load_query / campus_room_utilization_query | 位置语义失效；排名来源写死 | 一次 TopN 排名含并列时位置稳定、来源正确 |
| P-RESCHEDULE | 自然调课模拟（已选课程，省略教室） | RESCHEDULE_SIMULATION | Risk | campus_reschedule_feasibility | 为可选 room 发假教室查询或强制澄清 | 选定课程后问「这堂课能调到 X 吗（未提教室）」→ 可行性判断且无假 room 查找 |
| P-NOMUTATE | 调课绝不声称已执行 | RESCHEDULE_SIMULATION | Risk | —（输出边界） | 声称「已成功调课/已修改课表」 | 回答为 What-if 措辞，不含任何写操作声明 |
| P-ESCAPE | 无关新任务逃离旧 pending 状态 | NEW_TASK（stale escape） | Main | —（路由） | 沿用旧任务挂起状态 | 上一轮澄清未完成、本轮无关请求 → 直接新任务处理 |

## 多轮自然调课验收（P-RESCHEDULE + P-NOMUTATE）

必须满足以下结构化序列（执行时从匿名数据集中动态选择课程，不硬编码 fixture 实体/日期）：

```text
Turn 1: 通过自然课表请求找到/选定一节真实课程（如「某教师的某天课表」）。
Turn 2: 询问「这堂课」能否调到另一周/天/节次，不指定教室。
期望：Main → Risk；选中课程上下文保留；可行性工具收到的 target 不含假 room；
回答为 What-if（可行/冲突与约束），绝不声称课表已修改。
```

## 释义族（Paraphrase Families）

每个能力族至少覆盖三种语义变体（命令式 / 疑问式 / 口语简写），行为绑定目标族而非字面句：

```text
P-BROWSE      「列出几位老师」 / 「有哪些教室」 / 「老师清单」
P-TEMPORAL    「下周课表」 / 「这周有什么课」 / 「第3周课表」
P-AVAILABLE   「他们什么时候都有空」 / 「两位老师共同的空闲时间」 / 「谁和谁能一起开会的时间」
P-PLAN        「安排一个会议，给几个候选时段」 / 「帮我们找个能开会的时间+教室」 / 「出个方案」
P-RANK        「谁的课最多」 / 「教室利用率 Top3」 / 「最忙的老师」
P-RESCHEDULE  「这堂课能挪到周五吗」 / 「帮我看看这门课改到下周可行不」 / 「这节调个时间，不换教室」
```

## 执行纪律

- 每个 Agent 一次只粘贴一个基线 Prompt（顺序：Main → Schedule → Risk → Insight），回归可归因。
- 每个候选（含 ADP AI 一键优化输出）先 diff、再选择性合入 repo 源，绝不以平台生成文本作为唯一真源（见 `R50.2A-ADP-AI-PROMPT-OPTIMIZATION-GUIDE.md`）。
- 发现的新缺陷回到 repo 以 RED→GREEN 形式修复，不得只改控制台文本。
- Tool Direct Result 保持 OFF；R50.2A 期间不启用 Agent Output Widget。
