# R50.4 Runtime Acceptance（最小高价值验证集）

> 控制台升级 R50.4 双布局 Widget 后的验收清单（11 项最小集）。
> 每项都应由确定性工具产生真实结果后再截图；禁止用 mock 描述为生产验证。

## A. 布局路由（核心）

| # | 输入（用户语义） | 预期 Widget 形态 | 核对点 |
|---|---|---|---|
| A1 | 「查看教师003第1周课表」（整周） | **week-board 周视图** | 周一~周五板块、每日课程块含节次/课程名/教室/人员；空天折叠；「看某日明细」按钮存在；无「已核验」状态丢失 |
| A2 | 「查看教师003第1-2周课表」（周范围） | **week-board 周视图** | 跨周课程 meta 携带「第X周」；标题区显示第1-2周 |
| A3 | 「教师003周三的课表」（单日） | **result-card** | 单日明细以结果卡呈现，sections 逐条显示 |
| A4 | 空课表 / 无课程事实（整周） | **result-card 回退** | 自动回退结果卡且保留标题与兜底信息，不白屏 |

## B. 事实类结果卡

| # | 输入 | 预期 | 核对点 |
|---|---|---|---|
| B1 | 「检查教师003第1周的风险」 | result-card | 时间冲突 / 跨校区赶场分节呈现，badge 冲突/赶场 |
| B2 | 「查看负载第1名的课表」（TopN → 课表） | result-card → 进入课表后 A1 周视图 | 第1名教师课表按整周渲染 |
| B3 | 「查看教师003第1周课表」→ 点「检查这周的风险」 | 按钮 → 风险结果卡 | 按钮只触发 `sys.chat` 语义追问，不夹带内部标识 |
| B4 | 看整周课表 → 点「看下一个教学周」 | 下一周 week-board | 按钮文案与结果一致 |

| B7 | 「第1周校园教学态势」 | result-card | 各周课程量 / 负载 Top3 / 风险摘要 |

## C. 兜底

| # | 场景 | 预期 |
|---|---|---|
| C1 | 无结果（如不存在的教师） | 空结果卡 + 「扩大范围再试」 |
| C2 | 查询失败 / 实体未找到 | 错误卡（可重试 / 换一种问法） |

## 判定

- A1、A3、B1、B3、B5、B6 至少 6 项通过视为 R50.4 Runtime Acceptance 基本达成；
  剩余项记录为人工跟进，不阻塞交付。
- 任何一项出现内部协议文本（queryId / intent= / entityId / rankContext 等）即判失败并回滚 Widget 资产。
