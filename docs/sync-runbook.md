# FosuClass / 佛课小表 全校课程表同步与新学期发布运维手册

本手册详细介绍了佛大佛课小表（FosuClass）管理后台“全校课程表同步与新学期发布流程”的日常运维、新学期初始化、故障排查与应急响应方案，旨在保障课表更新流程的快速、稳定、安全与透明。

---

## 1. 核心概念与数据流向

在优化后的系统中，数据遵循以下流向，确保线上环境的安全：

```mermaid
graph TD
    A[教务系统 / 校园网内网] -->|CLI 同步脚本| B[本地 Staging JSON]
    B -->|后台上传与 Schema 校验| C[Staging 暂存区]
    C -->|对比 diff 预览与熔断检查| D{管理员确认发布?}
    D -->|是 (变动率>30%需要强勾确认)| E[正式 Release 快照]
    E -->|自动触发备份/热载入| F[备份区: server/data/backups]
    E -->|触碰 touch 配置| G[微信小程序数据更新]
```

* **Staging JSON**：管理员在本地或有校园网权限的电脑上运行同步客户端生成的完整快照 JSON。它是一份包含全校行政班、教师、教室、课程和对应排课数据的标准快照。上传 Staging JSON 到管理后台后，**不会立即影响线上小程序**。它必须经过后台的多重校验与人工确认，最后点击发布后才会激活。
* **Release**：当前正在线上运行的、小程序客户端直接拉取并解析的正式课表快照版本。
* **备份区**：每次发布新 Staging 或回滚版本时，系统会在 `server/data/backups/` 目录下自动以时间戳为后缀备份旧的 Release Snapshot，防止误覆盖。

## 2. 日常运维命令详解

后台“同步中心”命令说明卡片组对应以下 5 个核心命令：

### 2.1 快速同步 (npm run sync:quick)
* **命令**：`npm run sync:quick -- --term=2026-2027-1`
* **适用场景**：日常课表小更新、快速修复、刷新当前学期基础数据。
* **预计耗时**：1 ~ 3 分钟。
* **是否需要校园网**：是（需要直连教务网或 VPN）。
* **输出**：刷新当前 release 前的本地临时抓取缓存。
* **风险等级**：**低**。
* **常见失败原因**：登录 Cookie 过期、学校 DNS 故障、网络请求超时。
* **修复建议**：在本地运行 `npm run login` 重新登录授权后重试。

### 2.2 全量同步 (npm run sync:fresh)
* **命令**：`npm run sync:fresh -- --term=2026-2027-1 --start=2026-09-01`
* **适用场景**：新学期首次课表同步，抓取全校年级专业以重建行政班级排课。
* **预计耗时**：5 ~ 15 分钟。
* **是否需要校园网**：是。
* **输出**：在本地生存全量行政班级课表。
* **风险等级**：**中**。
* **常见失败原因**：高频请求触发教务网限流封禁、内网 VPN 掉线。
* **修复建议**：检查 `tools/fosu-sync-client/.env` 中的 `SYNC_CLASS_GRADES` 年级过滤参数，减少单轮抓取量。

### 2.3 资源同步 (npm run sync:resources)
* **命令**：`npm run sync:resources -- --term=2026-2027-1`
* **适用场景**：基于已有班级课表派生出教师课表、教室占用、全校课程以及构建教室热力图所需的资源维度数据。
* **预计耗时**：2 ~ 5 分钟。
* **是否需要校园网**：是（处理资源映射关系时需要校验教务实体信息）。
* **风险等级**：**中高**。
* **常见失败原因**：本地没有当前学期已抓取的班级课表缓存数据。
* **修复建议**：必须先运行 `npm run sync:fresh` 同步全校班级课表以产生基础缓存后，再运行此资源同步命令。

### 2.4 生成发布快照 (npm run sync:release)
* **命令**：`npm run sync:release -- --term=2026-2027-1 --note="2026-2027-1新学期课表首版"`
* **适用场景**：打包本地缓存数据，正式激活生成微信小程序端拉取的数据版本快照。
* **预计耗时**：15 ~ 30 秒。
* **是否需要校园网**：否。
* **风险等级**：**中（会立即影响小程序线上展示）**。
* **常见失败原因**：本地数据结构校验失败（如关键排课字段缺失）、ADMIN_API_TOKEN 配置无效。
* **修复建议**：运行下方格式校验命令，排查校验提示对数据源字段进行修补。

### 2.5 课程格式校验 (npm run test:course-normalizer)
* **命令**：`npm run test:course-normalizer`
* **适用场景**：每次发布快照或同步前运行，确保体育课多地点、教师地名正常化提取准确。
* **预计耗时**：1 ~ 3 秒。
* **是否需要校园网**：否。
* **风险等级**：**低**。
* **常见失败原因**：测试用例硬编码断言失败（通常是别名合并算法调整影响了既定特征）。
* **修复建议**：参考 `miniprogram/utils/courseNormalizer.js` 调整提取机制或补齐别名。

## 3. 新学期一键同步向导操作手册

### 3.1 什么是新学期同步聚合命令
当发布一个全新的学期课表时，手动分步执行上述命令容易出错。系统提供了一键同步向导聚合脚本 `npm run sync:new-term`：

```bash
npm run sync:new-term -- --term=2026-2027-1 --start=2026-09-01 --output=./staging/2026-2027-1-full.json
```

该聚合脚本会自动串联：
1. **校验学期代码和日期**。
2. **网络和登录诊断**。
3. **全量同步（fresh）及资源同步（resources）**。
4. **运行 course-normalizer 断言测试**。
5. **打包并生成本地 Staging JSON** 写入指定的 output 路径。

### 3.2 同步向导使用流程
1. **登录管理后台**，切换至“同步中心”页面。
2. 在 **新学期一键同步向导** 表单中输入参数：
   * **目标学期 (term)**: 例如 `2026-2027-1`
   * **学期开始日期 (StartDate)**: 选择开学首周的周一日期，如 `2026-09-01`
   * **发布说明 (releaseNote)**: 写明版本备注，如 `2026-2027-1 新学期全校课表首版`
   * **数据来源 (source)**: 选择数据同步路径。
   * **同步范围与操作模式**: 推荐选择“生成候选版本 (staging)”。
3. 拷贝向导框下方自动拼接生成的终端命令。
4. 在已建立教务网 VPN (EasyConnect) 的本地电脑或服务器终端执行该命令。
5. 执行完成后，会在终端最后打印出同步成果物统计摘要，并在本地产生 Staging JSON 文件（如 `./staging/2026-2027-1-full.json`）。

## 4. Staging JSON 上传与发布流程

### 4.1 上传与 Schema 校验
1. 将刚才生成的 Staging JSON 文件，拖拽或选择上传至“Staging JSON 上传、比对与发布”卡片的 Dropzone 区域。
2. 后台会立即执行多重格式校验：
   * **元数据校验**：必须包含 `schemaVersion`, `releaseVersion`, `term`, `termStartDate`, `generatedAt` 等。
   * **行政班空值阻断**：若 `classSchedules` 为空或不合法，直接阻断上传。
   * **资源缺损警告**：若 `teacherSchedules`, `classroomSchedules`, `courseSchedules` 等有部分缺失，允许通过但会生成黄色 Warning 警告。
   * **节次缺失清洗**：对于排课缺失节次的条目，直接清洗过滤以避免小程序崩溃；对缺失周次的条目允许通过但标记为 `[待确认]`。

### 4.2 差异 diff 比对与 30% 熔断保护
校验成功后，Staging 预览面板将会展示该 Staging 文件与**当前线上活跃 Release 快照**的差异数据：
* **实体数量变化 delta**（如行政班 +5 个，教室 -2 个等）。
* **行政班名单变动明细**（清晰列出本次同步删除了哪些班级，新增了哪些班级）。
* **30% 熔断安全保护**：
  > [!IMPORTANT]
  > 如果删除与新增班级的变动比例超过线上现存总量的 30%，系统会自动将“发布为正式版本”按钮置为危险状态，并强制锁死。此时必须由管理员仔细核对“行政班级变动明细”，确定无误后，手动勾选 **“我已知晓风险，确认本次数据变动为正常新学期更迭，强行发布”** 二次确认框，才允许发布。这能极大降低大一开学季误清空线上课表的风险。

### 4.3 正式发布
1. 点击“🚀 发布为正式版本”。
2. 后台在收到请求后，会首先将当前的线上快照复制一份存入 `server/data/backups/release-snapshot_[timestamp].json` 进行灾备。
3. 激活 Staging 数据为当前活跃版本，自动触碰小程序 `app-config` 的 dataVersion 版本号。
4. 线上微信小程序即时刷新缓存拉取最新课表，无感秒级完成切换。

## 5. 版本秒级回滚机制

如果新发布的课表数据出现大面积污染、教务网源头出错或排课冲突：
1. 在同步中心的 **版本发布历史与回滚控制** 表格中，查看最近发布的 5 个历史版本列表。
2. 找到需要恢复的历史版本（如上一个稳定版 `202620271-20260901-stable`）。
3. 点击 **⏪ 一键回滚** 按钮，并在浏览器弹出的二次确认中点击“确定”。
4. 后台会在回滚前再次对当前的异常版本做一份备份，然后秒级激活目标历史快照，更新同步元数据并触碰 `app-config`。
5. 小程序端会在 10 毫秒内感知并自动切换可见的课表数据，将损失降到最低。

## 6. 新生开学高峰期运营建议

新生开学前后（通常为 8 月底至 9 月中旬）是课表变动最频繁、也是运营压力最大的时期，建议遵循以下运营策略：

1. **新学期课表暂未开放容错**：如果教务系统尚未发布新生课表，请不要强行抓取或担心系统崩溃。如果管理员将后台学期配置（`currentSemester`）调为新学期但数据尚未同步完毕，系统会自动判定并动态向小程序端注入以下 Banner 公告：
   > “新学期课表正在同步中，请稍后查看。”
   以此防止新生登录后看到一片空白的异常界面。
2. **高频更新模式**：在开学前两周和开学后第一周，由于退补选课、教师调整频繁，建议**每天早上 7:00 和晚上 22:00 各自动/手动同步一次**。建议通过向导生成 Dry-run 模式在本地校验无误后，再上传 Staging 发布。
3. **别名(Alias)与模糊匹配**：如果新学期新生班级和专业名称发生小幅微调（例如“物联网241”和“物联网2024-1班”），可以在 `server/storage/catalog-meta.json` 中配置别名映射，以便新生在小程序端能够通过模糊匹配顺利查到课表。

## 7. 常见错误与排查指南

### 7.1 `100.fosu.edu.cn` DNS 解析失败或网络不可达
* **表现**：后台同步中心“校园网连通”显示为 **未连通 🔴**。运行同步脚本报错 DNS 无法解析。
* **原因**：由于教务系统网络仅在校园网内网公开，公网云服务器直接解析必然失败。
* **排查与解决**：
  1. 如果在云服务器上部署运行，此为正常现象。应在有校园网内网权限（或挂载了学校 VPN EasyConnect）的本地电脑上运行 sync-client 生成 Staging JSON，然后通过公网后台上传发布。
  2. 若在本地也解析失败，检查电脑是否成功登录 VPN，或直接尝试在浏览器中打开 `http://100.fosu.edu.cn` 确认网络是否通畅。

### 7.2 JSON schema 不合法，提示缺少关键元数据
* **表现**：上传 Staging JSON 时，后台报错提示“缺少关键元数据字段...”。
* **原因**：上传的 JSON 不是通过官方的 `sync.js` / `sync-new-term.js` 生成的完整快照，或者文件在传输中发生了损坏。
* **解决**：检查 Staging JSON 文件的头部，确保包含 `schemaVersion`, `releaseVersion`, `term`, `termStartDate`, `generatedAt` 以及 `classSchedules`。如果缺少，请重新使用最新版 CLI 客户端抓取生成。

### 7.3 发布 Staging 后，微信小程序仍然显示旧数据
* **表现**：后台提示发布成功，但手机端小程序显示的仍然是上个学期或上个版本的课表。
* **原因**：小程序端有本地缓存，或者后端没有成功更新 `app-config` 的 `dataVersion` 从而未能触碰失效。
* **解决**：
  1. 在后台健康检测中一键测试 `/api/fosu/app-config` 接口，检查返回的 `dataVersion.release` 字段是否已更新。
  2. 尝试在微信中下拉小程序，选择“重新载入”或者清理微信小程序缓存后重试。

### 7.4 行政班数量异常减少或缺失
* **表现**：同步后比对发现班级 delta 为较大的负数，或警告框中出现黄色 Warning。
* **原因**：抓取时教务网发生了限流拦截，导致只有前几个专业的课表被成功下载，后面由于请求超时全部为空。
* **解决**：
  1. 绝对不要直接发布该 Staging 文件！
  2. 检查抓取终端日志，分析抓取到哪个专业时开始报错。
  3. 适当调整 `tools/fosu-sync-client/.env` 中的抓取延迟间隔时间（增加延迟），或者在内网 VPN 重新拨号后重试。

### 7.5 教室占用热力图为空
* **表现**：小程序“空教室查询”或教室热力图界面显示空白，提示暂无数据。
* **原因**：在执行新学期同步时，仅运行了 `sync:fresh`（全量课表），遗漏了运行 `sync:resources` 资源派生同步命令。
* **解决**：重新通过向导生成包含资源派生的完整命令，或者在终端单独执行 `npm run sync:resources -- --term=2026-2027-1`。生成最新的包含完整 resources 结构的 Staging JSON 后重新上传发布即可。
