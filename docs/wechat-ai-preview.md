# 小序接入微信 AI 开发模式：隔离预览

## 定位与现阶段边界

微信 AI 开发模式把小程序功能封装为 Skill，供**微信 AI 的对话**调用。它是小序的一个外部入口，不会把微信模型注入佛课小表内的小序。正式版 `public` 的服务端 Agent Kernel 仍为确定性运行，外部 Provider 调用次数为零。个人今日课表、下一节课、记忆和提醒仍在小程序内处理。

微信[接入指南](https://developers.weixin.qq.com/miniprogram/dev/ai/guide.html)目前标为 beta，明确写着开发模式代码尚未开放正式提审，并要求不要把相关代码合入正式版提审。因此本仓库把接入源放在 `experiments/wechat-ai/`，由脚本只生成到 Git 忽略的 `dist/wechat-ai-preview/` 或带时间戳的预览工程。正式 `miniprogram/app.json` 不声明 `agent`。

## 已适配的任务

| 微信 AI 任务 | 原子接口 | 事实来源 | 页面入口 |
| --- | --- | --- | --- |
| 查班级、教师、教室、课程 | `searchCampusSchedule` | 已发布 Release Pack 搜索契约 | 全校搜索或真实 ID 对应的课表详情 |
| 找指定日期与节次的候选空教室 | `findEmptyClassrooms` | 已发布教学周 + 空教室索引 | 空教室页 |
| 查某天教学周 | `getTeachingWeek` | 已发布教学周历 | 周历页 |
| 个人课表、导入、提醒、记忆 | `openPersonalTask` 仅给小程序入口 | 小程序内受控流程 | 小序、个人导入页 |

原子接口通过 `wx.login` 和项目已有的会话 bootstrap 契约取得身份，只请求已有只读 `api/fosu` 数据路由。会话票据只写入受控请求头，不放入模型可见的 `content` 或 `structuredContent`。查询返回字段经过白名单裁剪，最多展示 8 项。原始课表、完整个人课表和管理员能力不由 Skill 返回。版本不匹配或事实源不可用时返回明确错误，不使用模型猜测补全。用户仍不应在微信 AI 对话框输入凭据或原始个人文件。

## 你在微信公众平台的配置

1. 在「基础功能 → AI 能力」保持截图中的「微信 AI」和「开发模式」开启；自动模式可保持关闭。本工程接的是开发模式 Skill。
2. 在「知识库 → 上传」选择 [`fosu-xiaoxu-public-faq.md`](../experiments/wechat-ai/knowledge/fosu-xiaoxu-public-faq.md)，确认上传后等待状态就绪。该文件仅含静态功能 FAQ，不含具体课表或个人数据。后台限制为最多 10 个文件、单文件小于 10 MB，当前文件满足限制。**不要**上传仓库其他含配置、课表原文或个人信息的文件。
3. 截图中的「知识库 → 调试」用于检查知识库召回；可选择「调试环境」，输入「小序能帮我做什么」和「如何导入个人课表」，确认回答符合文件内容。这个调试器不能代替 Skill 原子接口的真机验收。
4. 若页面显示微信 AI 评测或审核入口，先做开发/体验环境评测并保留结果；不要将 beta `agent` 代码合入正式版提审。

## 一键生成真机预览

在仓库根目录运行 `npm run preview:wechat-ai`。命令会运行隔离工程的接口测试，构建带时间戳的工程，通过已登录的微信开发者工具 CLI 生成 `dist/wechat-ai-preview-qr.jpg`。它只上传开发预览，不修改体验版/正式版，不提交正式审核。需要微信开发者工具 Nightly Electron Build、已登录且当前账号可预览本小程序；工具路径不在常见位置时可设置 `WECHAT_DEVTOOLS_CLI`。

也可先运行 `npm run build:wechat-ai-preview`，用开发者工具打开 `dist/wechat-ai-preview` 并选择「小程序 AI 编译」。预览工程基础库为 3.16.2，正式工程配置保持原值。开发者工具打开固定预览工程时 Windows 可能锁住目录，重新构建前先关闭该工程；一键预览用新目录避免锁冲突。

## 灰度手机验收

1. 用有微信 AI 灰度能力、且对这个 AppID 有开发预览权限的微信账号扫描本次二维码。若过期，重新运行一键预览命令。
2. 在微信 AI 对话中问「今天是第几教学周」。核对它给出的周数与佛课小表「教学周历」当前已发布数据一致。用户在 2026-09-17 的首次预览已经看到正确答案。
3. 问「查陈芳教师的课表」。应显示唯一教师匹配，并有可点击的**教师课表详情**入口；点击后检查页面是教师陈芳的课表，而不是全校课表默认「班级」页。首次预览出现后者；增加微信[页面接力与正文链接](https://developers.weixin.qq.com/miniprogram/dev/ai/integration.html)配置后，用户已在真机确认教师详情打开正确。
4. 问「今天第 3 到 4 节有哪些候选空教室」，核对日期、节次、候选说明和打开空教室页的路径。用户已报告真机查询基本正常。再分别试「我的下一节课」和「明天有什么课」：微信 AI 应给出对应的“小序 · 我的下一节课”或“小序 · 我的明日课程”入口，进入后由小程序内的小序处理。用户先前的真机复测仍被错误带到「今日」页，**此项尚未通过真机验收**。当前预览的[页面元数据](https://developers.weixin.qq.com/miniprogram/dev/ai/integration.html)除通用小序入口外，又为个人任务提供带固定 `q` 的专用卡片路径；自动测试会核对卡片路径与 `openPersonalTask` 返回值一致，但平台是否选用这些入口仍需真实微信 AI 验证。
5. 如仍跳错页，记录微信 AI 回复原文、点击的是正文蓝链还是下方卡片、最终打开的页面与脱敏 Trace。通用账号卡片可能由微信平台根据页面元数据生成；不能把它当作接口详情路径已经生效的证据。

运行 `npm run test:wechat-ai-preview` 以及仓库 Agent 必跑验证。DevTools 预览上传、Node mock 与手机实测分别记录，不互相替代。

## 进入正式版的条件

等待微信官方开放开发模式正式提审，并用当前文档、当前开发者工具与真机重新验证 Skill Schema、页面链接、隐私与能力授权。之后再单独评审是否将生成配置纳入正式包；不得用该入口绕开 `public` 零 Provider、服务端 Agent Kernel、Release Pack 和个人信息边界。
