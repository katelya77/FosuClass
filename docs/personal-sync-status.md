# FosuClass 个人课表同步功能现状与安全设计方案

本说明文档记录了“手动输入学号密码同步个人课表”功能的真实状态、隐藏的安全风险，以及为了正式发布而做出的 UI 拦截策略与未来的安全合规重构方案。

## 1. 个人同步功能当前真实状态

### 现状结论
**本功能目前为“仅 UI 占位 / 半成品 Mock”。**

- **前端状态**：原先的 `/pages/login/login` 页面仅包含两个输入框，点击后调用 `simulateSyncSchedule` 的延时模拟方法。
- **后端状态**：云函数 `cloudfunctions/syncSchedule/index.js` 尚未对接真实的强智教务系统（教务网域名 `100.fosu.edu.cn` 为内网或需要特定认证，公网直连无法绕过学校验证码等防御机制），且仅返回过滤后的 mock 数据。

## 2. 潜在安全与监管风险（极高）

如果在正式发布版本中保留学号密码的输入框，小程序将面临以下严重问题：

1. **违规收集用户敏感信息**：微信官方对于“收集教务网/统一身份认证的账号与密码”有极度严苛的安全审核规范。在缺乏第三方安全评估报告和隐私合规指引的情况下，**极易导致小程序提审被拒，或在运营期间被官方封禁、下架**。
2. **密码传输泄露风险**：代登录通常需要将密码明文或可逆加密传输至云函数，这使得用户的核心教务资产处于风险之中。

## 3. 本次上线前的临时安全处理

为了杜绝上述合规风险，同时给予用户合理的过渡提示，我们对 UI 进行了如下硬拦截：

- **设置页入口**：修改为 **“个人课表同步（内测中）”**。
- **全局拦截**：首页的所有“同步课表”、引导弹窗内的“同步个人课表”，以及设置页对应入口均通过 `wx.showModal` 拦截：
  > “个人账号同步功能正在内测。当前可先通过全校课表选择班级使用。”
- **登录页面重构**：重构了 `/pages/login/login`。如果用户依然以非常规手段跳转进入此页，将**绝对不会看到学号密码输入框和提交按钮**。页面已改造为静态解释说明页，详述合规安全原因，引导用户使用全校班级课表，并仅提供“返回首页”按钮。

## 4. 下一步安全合规方案规划 (Roadmap)

如果后续计划继续开发“个人课表同步”功能，必须按照以下原则进行改造以确保合规与安全：

### 方案 A：用户自行复制 HAR 离线解析（零密码风险，推荐）
- **实现流程**：引导用户在 PC 端登录教务系统，将课表请求的 `xskb_list.do` 数据包（或课表页面 HTML/JSON）导出为 HAR 或文本，在小程序中通过剪贴板或文件上传导入。
- **优点**：小程序及服务端**完全不接触用户密码**，无需模拟登录，100% 合规。

### 方案 B：云函数临时会话极速销毁（代登录机制）
若必须使用代登录：
1. **密码绝不落盘**：前端将学号密码经过 HTTPS 发送至云函数，云函数仅在内存中调用 Playwright/HTTP 客户端完成登录并爬取课表，然后**立即销毁密码与会话，绝对不在任何日志或云数据库中保存密码**。
2. **隐私协议声明**：在同步前增加显著的用户协议确认框，说明密码仅用于临时登录握手，并提供由第方机构出具的隐私合规证明。
