# R49.4.1 ADP Console Convergence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除 R49.3→R49.4 Prompt/Policy 遗留冲突，生成适合现有 5-tool ADP 插件无损升级到 7-tool 的控制台交接物，并用 D1~D5 真机证据冻结 R49.4-GOLDEN。

**Architecture:** Runtime/CloudBase 保持 R49.4 不变，本轮只收敛 Agent Prompt、handoff/context policy、E2E 契约与 ADP 控制台同步物。教师负载窗口排名的唯一动态事实源是 `campus_teacher_load_query`；`campus_overview` 只承担固定窗口校园整体态势。ADP 插件升级优先在现有插件上增量增加两个新 operation，避免删除插件导致现有鉴权和 Agent 绑定丢失。

**Tech Stack:** Markdown Agent prompts/policies, Node.js `node:test`, OpenAPI 3.0 JSON, Tencent Cloud ADP Multi-Agent custom API tools.

## Global Constraints

- 分支固定 `feat/campusflow-adp-integration`。
- PR #49 必须保持 OPEN / UNMERGED。
- 不新增第 5 个 Agent。
- 默认不修改 CampusTools Runtime、competition-demo-v2、CloudBase function、7 façade schema、Widget Runtime。
- Runtime 未改时不得重新部署 CloudBase；线上保持 `tools=9 / agentTools=7 / adpContractVersion=R49.4`。
- Main 只持有 `KnowledgeRetrievalAnswer`；7 个动态工具全部分配给三个子 Agent。
- 7 个动态工具的“工具调用结果直接返回给用户”全部 OFF。
- 每个新 Turn 由 Main 接管；Main clarification ON/Widget；Child clarification OFF；Main↔Child 中心化转交不变。
- 动态事实不得由 KnowledgeRetrievalAnswer 或模型记忆生成。
- ADP 当前截图仅显示旧 5 tools，因此 R49.4.1 Gate 必须包含插件从 5→7 的控制台升级。
