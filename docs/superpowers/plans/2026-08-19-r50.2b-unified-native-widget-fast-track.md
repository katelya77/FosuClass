# R50.2B Unified Native Widget Fast-Track Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the R50.2 Native Unified Agent Output Widget system, package one-shot ADP console cutover/rollback assets, and compress repo validation + prompt candidate checking + real-console acceptance into a single fast-track stage.

**Architecture:** Keep R50.2A semantics frozen and add a presentation layer only. Deterministic tool results are projected into a canonical `CampusResultEnvelope`; a single reusable Tencent Native Widget (`campus-result-unified-v1`) renders multiple variants for Schedule/Risk/Insight. Main remains text-first with clarification Widget. `sys.chat` actions send user-semantic continuation text back into the conversation; they do not perform business computation. Console configuration is delivered as one batch checklist with a text rollback path.

**Tech Stack:** Node.js CommonJS + `node:test`, existing Python/Tencent native Widget compiler assets, Tencent ADP Widget Template/Schema/Default format, Multi-Agent Agent Output Widget, official `sys.chat` Widget Action.

**Spec:** `docs/superpowers/specs/2026-08-19-r50.2-unified-native-widget-system-design.md`

## Global Constraints

- R50.2A at HEAD `c043c688469cfc77a138693d885a42f896353092` is the semantic baseline; do not regress it.
- Multi-Agent topology remains Main + Schedule + Risk + Insight.
- Main -> children; children -> Main; no child -> child semantic handoff.
- New user turns remain Main-first.
- CampusTools remains 13 unique Agent Tool operations / 14 bindings; no 14th operation.
- Main binds no CampusTools.
- Tool Direct Result remains OFF.
- Dataset remains `competition-demo-v3`.
- Primary result presentation is Agent Output Widget on Schedule/Risk/Insight only.
- Main remains text output + clarification Widget.
- Agent Output Widget disables streaming; keep cards concise and result-oriented.
- Widget failure must fall back to verified concise text; it must never break factual correctness.
- `sys.chat` is the only default continuation action for conversational follow-up; Widget templates contain no business computation.
- No real school identity, real timetable, token, NodeID, VarBizID, internal URL, raw `queryId`, raw `dataHash`, raw rank/temporal context or secrets in user-facing Widget payloads.
- PR #49 remains OPEN / UNMERGED. Do not formally publish the ADP app.

## Efficiency Rule

This stage deliberately removes the old stop-start workflow. OpenCode should finish Tasks 1-8 repo-side in one execution run. After that the user should perform **one ADP console session**: import/select one unified Widget, paste/update four prompts, optionally run AI optimization for all four and batch-gate candidates, bind Widget to the three child Agents, then execute the 12-case acceptance matrix. Only failures that reproduce in that session create a new engineering loop.
