# R49.4 Multi-School Anonymous Data Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the R49.3 “four-week aggregate → silently drill down to week 1” shortcut with deterministic range-aware ranking/schedule tools, while laying an institution-neutral, privacy-first schedule-ingestion foundation without exposing any private timetable or real-school identity in competition artifacts.

**Architecture:** Keep the existing Main/Schedule/Risk/Insight Multi-Agent topology. Add two deterministic lower-level CampusTools (`query_teacher_load`, `query_schedule_range`) and two ADP Agent Tool façades (`campus_teacher_load_query`, `campus_schedule_range_query`), then make Main/Insight/Schedule carry an explicit `WindowContext` instead of converting an aggregate count into an academic week. In parallel, create an isolated `r49-ma/data-hub` foundation with canonical schedule schema, week-expression parser, neutral adapter interfaces, synthetic fixtures, and privacy gates; no live login/VPN scraping or real-file import is shipped in R49.4.

**Tech Stack:** Node.js >=18, CommonJS, TypeScript contracts, `node:test`, JSON Schema/OpenAPI 3.0, Tencent CloudBase HTTP Function, Tencent ADP Multi-Agent + custom API plugin.

## Global Constraints

- Work on `feat/campusflow-adp-integration`; keep PR #49 **OPEN / UNMERGED**. Do not merge or publish a formal application.
- Preserve `competition-demo-v2` as the active runtime dataset and keep `dataHash=sha1:4f3bbbb45d1f` unless an explicitly reviewed data change is made; this plan requires no data-file modification.
- The real uploaded `.xls`, its local filename, real student identity, real university name, real teacher/class/course/room values, private portal/VPN hostnames, cookies, tokens, SSO tickets, or screenshots must never be committed, copied into fixtures, written into prompts/reports, or included in submission assets.
- New compatibility IDs are capability/provider-family IDs only: `portal-family-qz-legacy`, `portal-family-cas-a`, `portal-family-cas-b`.
- Dynamic campus facts remain deterministic. Agents may interpret intent and route, but may not count schedules, rank teachers, infer dates, or invent campus facts from model memory/knowledge.
- Preserve R49.2.1 zero-mask behavior: optional integer values normalized to `0` by ADP are “not specified” where the existing contract says so; do not reintroduce `[0,0]` filtering bugs.
- Preserve R49.3 rank semantics: Top1/Top2/Top3 are stable list positions, metric ties do not trigger clarification.
- R49.4 changes the **time-window policy**: a four-week ranking followed by “看Top1课表” preserves weeks 1..4; it must not silently become week 1 or week 4.
- A multi-week ranking followed by ambiguous `检查Top1风险` must not silently use week 1. Until range-aware risk exists, Main must request one concise time-window clarification unless the user explicitly specifies a week/date.
- Tool “调用结果直接返回给用户” remains **OFF** in ADP.
- Do not implement credential login automation, VPN bypass, live protected-portal scraping, screenshot vision extraction, official-web crawling, long-term memory, or user-facing import Widget in this R49.4 slice.
- Use `competition/adp-kit/mcp/campus-tools-mcp/src` as the authoritative runtime source. After runtime edits, run `node competition/adp-kit/cloudfunctions/sync-campusflow-function.js`; do not hand-maintain divergent MCP/CloudFunction copies.
- Do not weaken existing A~H / 13 core / R48 regression assertions just to make tests green. Replace obsolete R49.3 week=1 assertions with stronger R49.4 range assertions.
