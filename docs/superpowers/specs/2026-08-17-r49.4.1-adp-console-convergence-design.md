## 1. 目标

R49.4.1 不新增业务能力、不增加 Agent、不修改匿名比赛数据事实层。它只做两件事：

1. 消除 R49.3 → R49.4 升级后遗留在 Agent Prompt / policy / checklist 中的语义冲突，确保教师负载排名、跨域 TopN 下钻与时间窗口全部使用 R49.4 的唯一语义；
2. 把 R49.4 在腾讯 ADP 控制台真实同步并完成 D1~D5 真机验收，形成进入 R49.5 前的稳定 Golden Baseline。

成功标准不是“本地测试全绿”，而是：仓库真源无冲突 + ADP 插件 7 operations + 4 Agent Prompt 与工具绑定正确 + D1~D5 真机行为与工具证据完全符合契约。

## 2. 当前已确认事实

- 当前 R49.4 Runtime 已具备 9 个底层 CampusTools、7 个 Agent Tool façade。
- 新增 Agent Tool：
  - `campus_teacher_load_query`
  - `campus_schedule_range_query`
- `campus_teacher_load_query` 是任意教学周窗口教师负载排名的权威工具。
- `campus_schedule_range_query` 是跨多周课表下钻的权威工具。
- `campus_overview` 继续负责固定窗口校园整体教学态势，不应被描述为所有教师负载窗口排名的唯一来源。
- R49.4 WindowContext：
  - `rankingWindow`：排名/聚合窗口；
  - `detailWindow`：下钻课表窗口；
  - `academicWeek`：用户显式指定的单周。
- 多周排名后“看 Top1 课表”继承 rankingWindow 为 detailWindow；不得默认 week=1，也不得把窗口 count=4 当 week=4。
- 多周排名后“检查 Top1 风险”若用户未指定周次/日期，当前因无 range-risk 工具必须由 Main 澄清时间窗口。

## 3. 已发现的 Prompt 一致性问题

### 3.1 Main Orchestrator

当前 Prompt 的 R49.4 WindowContext 规则已经正确，但 R49.3 Rank Context 仍残留过强的 `campus_overview.teacherLoadTop` 来源绑定。

风险：模型可能把所有 Top1 教师负载来源都解释为 overview，而忽略 R49.4 新增的 `campus_teacher_load_query`。

目标：把 Rank Context 改成来源可追踪但不写死为 overview 的统一结构，例如：

```json
{
  "sourceTool": "campus_teacher_load_query",
  "sourceDomain": "teacher_load",
  "rankingWindow": {"weekStart":1,"weekEnd":4},
  "selectedRank": 1,
  "entities": []
}
```

具体字段名可沿用现有协议，关键是不能再把教师负载排位语义限定为 `campus_overview.teacherLoadTop`。

### 3.2 Campus Insight

当前 Prompt 同时存在两套规则：

- 新规则：教师负载窗口排名调用 `campus_teacher_load_query`；
- 旧规则：动态负载数字全部来自 `campus_overview`，窗口变化 fresh 调 `campus_overview`。

这是明确冲突。

目标职责拆分：

- `campus_teacher_load_query`：教师负载、TopN 教师、任意 weekStart..weekEnd 排名；
- `campus_overview`：校区整体态势、空间压力、整体教学规模、全局风险、固定窗口概览；
- 若用户同时要求“未来四周教师负载 + 全局校区态势”，允许同轮按任务拆分分别调用相应工具，但不得让一个工具替代另一个工具的职责。

## 4. R49.4.1 唯一语义

### 4.1 Teacher Load Ranking

用户问：

- “未来四周教师负载最高的是谁”
- “未来第一周课表负载最高的教师是谁”
- “第2到第4周教师负载 Top3”

必须使用：

`campus_teacher_load_query(weekStart, weekEnd, topN)`

不得：

- 从 KnowledgeRetrievalAnswer 回答；
- 从旧 overview 历史结果猜；
- 用模型自己数课；
- 因业务指标并列而澄清 Top1。

Top1/Top2/Top3 均是稳定排序后的 position 语义。

### 4.2 TopN Schedule Drilldown

若本轮 rankContext 来自 W1..W4：

“看 Top1 课表” → `detailWindow=1..4` → `campus_schedule_range_query`。

若随后说：

“只看第一周” → 显式覆盖 → fresh `campus_schedule_query(week=1)`。

不得将：

- `rankingWindow.weekEnd=4` 解释为 `week=4`；
- 多周窗口静默缩窄成 week=1。

### 4.3 TopN Risk Drilldown

若 rankContext 来自多周窗口，用户只说“检查 Top1 风险”：

- 保留 Top1 实体；
- 不继承多周范围作为 risk 单周参数；
- Main 必须澄清“要检查第几周或哪一天”；
- 不允许默认为第1周。

用户明确“检查 Top1 第一周风险”后才调用：

`campus_risk_check(mode=self, entity=Top1, week=1)`。

### 4.4 Fresh Tool Call

任何新 Turn 改变下列动态 slot，都必须 fresh 调相应工具：

- 排名窗口 / topN / campus；
- schedule 的 entity / week / range / weekday / date / period；
- risk 的 entity / week / date；
- day-plan 的 date。

解释型追问可基于已核验结果，不强制重复取数。

## 6. Prompt Consistency Gate

新增自动化测试，至少检查：

1. Main/Insight 明确声明教师负载窗口排名使用 `campus_teacher_load_query`；
2. 不允许出现“所有教师负载/窗口变化都必须调用 campus_overview”类旧规则；
3. rankContext 来源不得硬编码为 overview-only；
4. Schedule 多周 detailWindow 必须使用 `campus_schedule_range_query`；
5. Risk 多周 rank 下钻未给单周/日期时必须 NEED_CLARIFICATION；
6. 不允许重新引入默认 week=1；
7. 不允许把 rankingWindow/weekEnd/count 映射为单周 academicWeek；
8. Top1 并列保持 position 语义、NO CLARIFICATION。

测试必须在旧 Prompt 上能失败，在修复后变绿，不能只检查文件存在或关键词数量。

## 8. D1~D5 真机验收

使用一个全新会话按顺序执行并截取工具证据。

### D1

用户：`未来四周教师负载最高的是谁？`

必须：

- `campus_teacher_load_query`
- `weekStart=1`
- `weekEnd=4`
- Top1/Top2 来自真实排序
- 指标并列时可说明并列，但不得澄清“选谁做 Top1”

### D2

用户：`看Top1课表`

必须：

- 不澄清 Top1；
- 继承 D1 Top1 实体；
- `campus_schedule_range_query`
- `weekStart=1, weekEnd=4`
- 结果包含多周 academicWeek。

### D3

用户：`只看第一周`

必须 fresh：

- `campus_schedule_query`
- `week=1`
- 不能通过裁剪 D2 文本直接回答。

### D4

新会话：`看未来第一周课表负载最高的教师课表`

必须链路：

1. `campus_teacher_load_query(1,1)`；
2. 稳定 Top1；
3. `campus_schedule_query(Top1, week=1)`；
4. 不走知识库；
5. 不出现 Main ↔ Insight 循环。

### D5

新会话：

1. `未来四周教师负载最高的是谁？`
2. `检查Top1风险`

必须：

- 保留 Top1 实体；
- Main 发起时间窗口澄清；
- 此时不得调用 `campus_risk_check(week=1)`；
- 用户补充“第一周”后 fresh `campus_risk_check(mode=self, Top1, week=1)`。

## 10. R49.5 下一阶段边界

R49.5 名称：`Multimodal Schedule Studio`。

目标：把文件、Excel/CSV、截图/图片课表统一转换为匿名 Canonical Schedule，经 validator、低置信度澄清、预览确认后进入个人课表上下文，随后可被 Schedule/Risk/Planning 使用。

- 比赛版本不绑定真实学校身份；

R49.5 不属于本设计的实施范围；R49.4.1 真机 Gate 未通过前不得并行引入多模态导入变量。
