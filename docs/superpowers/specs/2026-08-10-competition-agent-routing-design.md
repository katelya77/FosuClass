# 校园智序 · 小序：应用级路由与多轮上下文设计

日期：2026-08-10
分支：`feat/campusflow-adp-integration`

## 1. 当前基线

四条基础工作流已经完成真实 ADP 端到端验收并冻结：

- 01 多维课表查询：FROZEN
- 02 空教室规划：FROZEN
- 03 课程冲突比较 V4.1：FROZEN
- 04 今日校园计划 V1.1：FROZEN

冻结含义：总 Agent 集成阶段不再复制或改写四条工作流的动态事实逻辑；只有真实集成回归才允许解冻。

## 2. 架构选择：不新增“00 总路由工作流”

应用继续使用 ADP 标准模式。

总路由职责交给标准模式应用自身的 Agent：

`用户消息 -> 应用级意图理解/上下文 -> 选择已启用工作流或知识库 -> 01/02/03/04 -> 确定性 CampusTools -> 回复`

不创建第五条“总路由工作流”，原因：

1. 标准模式原生支持添加并调用多个工作流。
2. 工作流用途由名称、描述和示例帮助模型理解。
3. 已启用工作流可被应用正常调用，停用工作流不能被应用正常调用。
4. 再造一个路由工作流会重复平台已有 Agent 路由职责，并引入工作流节点引用、输入映射、发布状态和导入格式等额外故障面。
5. 01-04 已是稳定执行器，应让上层只做选择与上下文，不重复业务计算。

## 3. 路由意图

应用层只在五类能力间选择：

### 3.1 `query_schedule` -> 01

用于单个班级、教师、教室或课程的课表/占用安排。

典型：
- 教师001周三有什么课
- A班周五下午有课吗
- A1-101今天谁在用
- 高等数学A第1周什么时候上

排除：
- “空教室/哪里自习” -> 02
- 两个对象比较、冲突、撞课、赶场 -> 03
- 第一人称个人当天安排/怎么过/今天课多不多 -> 04

### 3.2 `find_available_classrooms` -> 02

用于寻找可用空间、自习位置、容量/楼栋/连续节次约束。

强触发词：
- 空教室
- 空闲教室
- 哪里可以自习
- 能坐 N 人的教室
- 连续 N 节可用

“某教室什么时候被谁使用”不是空教室检索，走 01。

### 3.3 `compare_schedules` -> 03

用于两个实体的冲突比较，或单一教师自身的跨校区赶场风险检查。

强触发：
- 冲突
- 撞课
- 比较 A 和 B
- 两边都有课吗
- 赶场 / 跨校区来得及吗

单对象“教师003周一有什么课”仍走 01；单对象“教师003周一跨校区来得及吗”走 03 self-compare。

### 3.4 `generate_day_plan` -> 04

用于匿名演示用户的第一人称日计划：个人课程时间轴、空档、自习建议、校区偏好和赶场提醒。

强触发：
- 今天/明天我怎么安排
- 帮我规划一天
- 今天课多吗
- 我想连续自习 N 节，怎么安排
- 我偏好校区A，帮我看看明天

若用户明确说“找空教室”而不是规划个人一天，优先走 02。

### 3.5 `knowledge` -> 知识库

产品说明、教学周规则、数据边界、匿名赛事规范、工具能力/失败规则等稳定知识使用知识库，不触发动态工作流。

## 4. 路由优先级

当一句话同时包含多个信号时，使用以下优先级，而不是简单关键词命中：

1. 明确“两实体比较/冲突/赶场风险” -> 03
2. 明确“空教室/空间搜索” -> 02
3. 明确第一人称“个人日计划/怎么安排一天” -> 04
4. 单实体课表/占用 -> 01
5. 稳定知识 -> 知识库
6. 都不匹配 -> 应用 fallback

特殊歧义：

- “今天有课吗”没有指定班级/教师，视为匿名个人日计划 -> 04。
- “A班今天有课吗”指定了班级，走 01。
- “没课的时候去哪自习好”作为个人日计划问题走 04；“现在有哪些空教室”走 02。
- “教师003周一跨校区来得及吗”走 03，而不是 01。

## 5. 多轮上下文合同

总原则：只继承最近一次已确认、仍属于当前任务语义的槽位；新值覆盖旧值；切换任务时删除无关槽位。

### 5.1 01 内部继承

允许继承：
- entity_type
- entity_name
- date/week/weekday
- period_scope

示例：
- 用户：`教师001周三的课`
- 用户：`那周五下午呢`
- 应继承教师001，只更新时间。

### 5.2 02 内部继承

允许继承：
- campus
- date/week/weekday
- period range
- building
- capacity

用户明确新校区后覆盖旧校区。

### 5.3 03 内部继承

允许继承：
- first entity
- second entity
- date range
- period scope

示例：
- `比较A班和B班`
- `再和D班比一下`

应把已确认的主要参照对象与新 D 班组成下一次比较，不从更早轮次恢复已被覆盖实体。

### 5.4 04 内部继承

允许继承：
- preferred_campus
- preferred_study_duration
- 同一日计划任务中的日期条件

已真实验证：先指定“偏好校区A”，下一轮只说“连续自习2节”时可以继承校区A；清空上下文后不能凭空出现该偏好。

永不继承/永不接受覆盖：
- visitorId。始终固定为 `visitor-demo-001`。

### 5.5 跨工作流继承

默认不跨工作流复制参数。

只允许明确的指代式 handoff：

- 01 -> 03：`教师003周一的课` 后说 `再和A班比较一下`，可把最近已确认的教师003作为第一比较对象。
- 01 -> 02：不得把查询课表中的教室/校区自动视为用户的空教室搜索条件，除非用户明确指代。
- 02 -> 04：空间查询的 campus 不自动变成个人偏好；用户必须明确说“那就按校区B帮我规划”。
- 04 -> 02：日计划里展示的推荐教室不自动变成新查询实体；必须有用户明确追问。

## 6. 上下文清理规则

出现以下行为之一，视为新任务并清理无关槽位：

- 用户明确切换能力类别，例如从“查教师课表”切到“找空教室”。
- 用户给出完整的新实体集合。
- 用户点击/触发清空上下文。
- 上轮为错误/不存在实体，除非用户本轮是在修正该实体。

不得继承：

- `ENTITY_NOT_FOUND` 的非法实体
- 工具错误参数
- 模型自己推测但未被工具/用户确认的值
- 任何真实身份/visitor 注入

## 7. 应用级角色指令增强

现有 12 条安全/事实规则继续保留，并增加“工作流选择”段：

- 01：单实体课表/占用
- 02：空教室/自习空间
- 03：两实体冲突或跨校区赶场
- 04：匿名个人日计划
- 稳定知识：知识库

禁止为了“看起来更智能”同时调用多个工作流回答一个本可由单工作流完成的问题。

若用户请求确实包含两个独立任务，例如“先查A班周五课程，再看看下午有哪些空教室”，允许拆成两个连续任务；先完成第一个并保留用户明确给出的公共时间条件，再执行第二个。不要把两个工具结果在未核验情况下自行融合成新事实。

## 8. 工作流描述要求

四条工作流描述必须包含：

- 正向用途
- 明确排除项
- 2-4 个高区分度示例

目的不是堆关键词，而是降低 01/02/03/04 之间的边界重叠。

## 9. ADP 平台操作顺序

1. 保持应用为标准模式。
2. 在工作流管理页确认 01/02/03/04 均为冻结版本。
3. 将 01/02/03/04 的“是否启用”全部开启；未启用工作流不能由应用正常调用。
4. 不发布正式应用，先在应用测试窗验证自动路由。
5. 更新应用角色指令和欢迎示例。
6. 跑应用级路由 smoke。
7. 再接 Widget 与完整 80 条评测。

## 10. 第一轮应用级路由 Smoke

每组先清空上下文：

1. `查询教师001第1周周三的课程` -> 01
2. `校区A 2026-09-03 下午有哪些空教室` -> 02
3. `比较A班和B班第1周的课程冲突` -> 03
4. `帮我看看2026-09-04的安排` -> 04
5. `A1-101今天被谁使用` -> 01
6. `找个校区A能坐60人的空教室` -> 02（若缺时间则由 02 追问）
7. `教师003第1周周一跨校区来得及吗` -> 03
8. `今天有课吗` -> 04
9. `教学周是怎么计算的` -> 知识库
10. `帮我写一首诗` -> fallback，不调用 01-04

## 11. 多轮 Smoke

不清空同组上下文：

### A. 01 内继承
- `教师001第1周周三的课`
- `那周五下午呢`

### B. 02 内继承
- `校区A 2026-09-03 下午有哪些空教室`
- `那校区B呢`

### C. 03 内继承
- `比较A班和B班第1周`
- `再和D班比一下`

### D. 04 内继承
- `我偏好校区A，帮我规划2026-09-04`
- `那天想连续自习2节`

### E. 跨工作流明确 handoff
- `教师003第1周周一的课`
- `再和A班比较一下有没有冲突`

## 12. 通过标准

进入 Widget 阶段前必须满足：

- 10 条单轮路由 smoke 全部调用正确能力或正确 fallback。
- 4 组同工作流上下文继承正确。
- 1 组明确跨工作流 handoff 可正确执行。
- 不出现同一句误调用多个冻结工作流。
- 动态事实仍全部由工作流/CampusTools 返回。
- visitor 注入无效。
- 所有非法/缺失参数仍由对应冻结工作流自行追问或返回确定性错误。

通过后冻结“应用级路由契约”，进入 Widget 与 80 条评测收敛。
