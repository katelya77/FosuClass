# 小佛助手产品体验审计（根因分析）

> 审计对象：`packageXiaofu/pages/ai-assistant` 及关联 Sheet 组件  
> 基线：`831f748b`（PR #22 Final Convergence）  
> 目的：在动手改样式之前，明确「为什么不像成熟助手」——不是配色问题，而是信息架构与交互契约错误。

## 1. 页面不好看 ≠ 配色问题：顶部信息架构错误

### 现象

页内顶部同时出现：品牌识别、对话名、运行模式 Chip、记忆 Chip、对话按钮、「?」帮助、「⋯」更多。系统导航栏已写「小佛助手」，页内仍保留品牌与状态堆叠。

### 根因（代码）

| 位置 | 问题 |
|------|------|
| `ai-assistant.wxml` header | 头像 + 对话标题 + `statusChips` 循环 + `memoryChipText` + **三个**文字按钮（对话 / ? / ⋯） |
| `refreshConnectionStatus` | Chip 可叠加 runtime 文案 +「已同步/会话记忆」；`memoryChipText` 再单独渲染，**状态重复** |
| `.xiaofu-header` | 白底、圆角、阴影，形成「厚重卡片」而非导航附属条 |
| 能力说明 | 与「更多」并列暴露，抢占主任务注意力 |

### 因果

用户打开助手时，首屏焦点应是「我要完成什么任务」。当前首屏焦点是「系统现在什么模式、记忆开没开、还有哪些按钮」——**系统状态抢占用户任务**，同一级内容过多导致顶部拥挤，廉价感和工程面板感由此产生。

### 修复方向

- 高度 92–112rpx，与背景融合，无大阴影/大圆角容器。
- 主信息：对话标题；副信息：一行组合状态。
- 仅两个图标入口：对话列表 / 更多。
- 能力说明进入更多；标题点击打开对话列表。
- 状态去重：一个组合字符串（如「增强模式 · 已记住上下文」），不展示 Provider/Model/planner/runId。

## 2. 不像智能体：每条回复后的系统组件堆叠

### 现象

助手回复后固定出现：反馈区（👍👎···）→ 建议 Chip →（事实任务时）任务轨迹 / Evidence / 卡片。用户看到的是「系统模块清单」，不是「一个智能结论」。

### 根因

| 位置 | 问题 |
|------|------|
| `feedback-row` 默认 `wx:if` | 每条有内容的助手消息都渲染反馈，占一整行 |
| `suggestion-row` | 建议常机械重复（如「你能帮我做什么」） |
| `normalizeMessageForDisplay` | plain 模式已能剥卡/轨迹，但 UI 仍默认挂反馈与建议展示层 |
| 多模块并列 | 气泡 + 反馈 + 建议 + 卡 + 来源 = 多个视觉焦点 |

### 因果

成熟助手是 **One Answer, One Focus**。强制展示模块数量会掩盖智能体验，把对话页变成控制台。

### 修复方向

- 删除默认 feedback-row；反馈仅长按/菜单后进入，完成只 Toast。
- 建议：问候 ≤2、相关、去重、稳定多轮可隐藏。
- 普通问候：无轨迹、无 Evidence、无结果卡。
- 事实任务：正文 + 最多一张主卡；轨迹默认折叠。

---

## 3. 「更多操作」文字不清晰：布局契约错误

### 现象

记忆行出现「记忆：会…」类截断；标题、状态、箭头挤在同一横排；关闭是大胶囊「关闭」。

### 根因

```css
.header-menu-row-meta {
  max-width: 40%;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

| 问题 | 说明 |
|------|------|
| 同一横排塞标题+状态+箭头 | 状态挤压标题，小屏必截断 |
| `max-width: 40%` + ellipsis | 设计层强制省略，不是「字太多」 |
| `mapMemoryModeText` | 「记忆：仅本机」等内部口吻，易被截成「记忆：会…」类观感 |
| Sheet 未成体系 | 关闭大按钮、无分组、无图标行、无 Switch 模式 |

### 因果

点击区域、文本区域、信息层级未分离 → 用户读不懂当前记忆状态，也不像微信原生设置页。

### 修复方向

- 统一设置 Sheet：分组（对话 / 个性化 / 帮助 / 危险）。
- 行结构：图标 · 标题 · 副标题换行 · 右侧状态/Switch · 箭头。
- 完整中文状态：「仅保存在本机」「已保存会话状态」「已开启跨设备同步」。
- 小型 X 关闭；危险操作二次确认；Safe Area；≥44px 点击区。
- **删除** meta `max-width: 40%` 截断契约。

## 4. 回复繁杂：多焦点消息栈

### 现象

大白气泡 + 每条重复头像 + 固定反馈 + 建议 Chip + 轨迹/Evidence/卡。

### 根因

| 位置 | 问题 |
|------|------|
| `.message-row.assistant .message-bubble` | 助手也用厚重白气泡，像卡片堆叠 |
| `showAvatar` | 已支持分组，但样式仍偏大、视觉仍「每条一块」 |
| 反馈默认常驻 | 见 §2 |
| 卡片列表 | 可见操作与卡数量未按产品上限严格收敛到「一焦点」 |

### 因果

同一条回复多个视觉焦点 → 信息噪声高，像 Demo 不像 Copilot。

### 修复方向

- 助手正文贴页面背景排版，无大白气泡。
- 连续助手消息只在首条显示小头像。
- 用户气泡：降饱和品牌红、max-width ~78%、弱阴影。
- 时间弱化、同分钟可省略。
- 卡片：普通 0 / 单事实 1 / 复合默认 1 上限 2；可见操作 ≤2。

## 5. 功能很多但不显智能：能力以列表暴露

### 现象

欢迎区四张厚重任务卡 + 横向 quick-action + 任务工具条；用户必须理解模块才能点。

### 根因

能力入口以 **列表/网格** 为主路径，自然语言与上下文选择能力未成为默认心智。Agent Kernel 已能 Tool 选择，但 UI 仍像「功能目录页」。

### 因果

用户负担从「描述目标」变成「理解系统模块」——与 Conversation First 相反。

### 修复方向

- 空状态：轻量两列入口 + 一句示例，开始聊天后完全收起。
- 「+」打开快捷（工具/导入/地图/语音/新对话），非常驻功能墙。
- 隐藏 Planner/RAG/Tool/Provider 内部概念；只展示可核验任务轨迹（真实 Run Event）。

---

## 6. 输入区：表单感而非聊天输入

### 现象

独立「↵」换行按钮 + 发送 + 长期摘要说明 `composer-note` → 多层高度、像表单。

### 根因

WXML 中 `newline-btn` + `composer-note` 常驻；摘要状态不应占据输入区次级行。

### 修复方向

单层 composer：`[+]` · textarea(1–5 行) · 语音 · 发送/停止；隐私/摘要进更多；删除独立换行按钮。

---

## 7. 审计结论（先于设计）

| # | 表象 | 真正根因 | 不是 |
|---|------|----------|------|
| 1 | 顶部拥挤难看 | 同级信息过多 + 状态重复 + 卡片化 header | 单纯换色 |
| 2 | 不像智能体 | 默认系统组件堆叠 | 缺更多功能入口 |
| 3 | 更多菜单看不清 | 横排 + max-width 截断 + 无设计系统 | 字号差一点 |
| 4 | 回复繁杂 | 多视觉焦点消息栈 | 内容太多无法改 |
| 5 | 不显智能 | 能力列表优先而非对话优先 | 后端不够强 |

后续设计与实现必须按 **Conversation First / One Focus / Progressive Disclosure / Native Mini Program / No Fake Intelligence** 收敛，而不是「再加一层美化 CSS」。

## 8. 本轮必须删除的默认 UI

- 默认 👍 / 👎 / feedback-row / 反馈详情常驻
- 顶部三并列文字按钮与重复状态 Chip
- 独立换行按钮
- 输入区常驻摘要说明
- 旧 `.header-menu-row-meta { max-width: 40% }` 截断布局
- 助手厚重大白气泡与无差别逐条头像
- 内部标签与工程诊断信息（Provider 名等）出现在用户默认路径

## 9. 与后端边界

- 不重写 Kernel / Planner / Hybrid RAG / Memory / Run Events
- 不破坏 public 零外部模型
- Feedback API 可保留，前端默认不暴露
- 仅允许 Presentation / 前端 ViewModel 与少量体验字段
