# 公告表情回应

公告支持每个已验证微信账号一个当前表情，可以切换或撤回，不提供文字评论、用户列表或个人资料。未导入课表也能使用；身份来自现有微信会话，与个人课表、助手和模型无关。

首页公告条展示最多三个热门表情和回应总人数。点击打开详情，长按公告或详情正文直接展开表情面板；详情中也有明确的加号入口。选中表情使用红色边框与勾选标记，再点可撤回。短公告保持居中，长公告与表情面板在详情内部滚动，收起按钮保留在底部。

首页内容后台可为每条公告开放或关闭互动，选择 24 个内置表情中的任意非空集合，查看真实汇总。关闭互动保留旧计数；移出可选列表的旧表情不会删除历史回应，用户仍能撤回。手机预览可点开详情、选择、切换和撤回；预览操作只影响预览，不发送真实回应。

## 接口与持久化

- `GET /api/fosu/notices/:id/reactions` 返回公开汇总；有效会话额外返回当前用户的选择。
- `PUT /api/fosu/notices/:id/reactions` 只接受 `{emoji: "like"}` 等稳定 ID，`{emoji: null}` 撤回。有效会话是所有模式下写入的必要条件。
- 同一目标的重复 PUT 幂等。每账号每分钟最多 40 次操作（30 次基础额度加 10 次突发额度）；每公告最多十万人回应。
- 公告停用、未开始、到期、被删除或公告模块停用时，不允许读写互动。每日知识与系统临时提示不参与。
- 每条公告独立文件存储于 `FOSU_STORAGE_DIR/notice-reactions/`。仅保存再次散列的账号标识和表情 ID，不保存 OpenID、会话票据或个人课表。对外不输出账号标识。
- 同步临界区及文件锁保护多人/多进程写入，原子替换保存。遇到锁冲突返回可重试的 503；损坏文件拒绝写入，不能当作空票覆盖。宿主意外终止留下锁目录时，由运维确认无在途写入后移除相应 `.lock` 目录。
- 源目录已加入 Git 忽略；生产部署完整存储备份涵盖回应。删除公告后保留独立回应文件，以支持通过现有公告备份恢复原 ID；不提供后台清空或伪造计数入口。

表情目录以 `server/src/content/noticeReactions.js` 为唯一源，`tools/generate-notice-reactions.js` 生成小程序兼容文件，`build:miniprogram-compat` 已接入生成。服务端容器不依赖小程序源目录。

## 验证与回滚

运行 `npm run test:notice-reactions` 验证真实本地接口、组件状态机与后台浏览器交互。浏览器截图数据为隔离测试数据，不是生产回应。还应运行公告/首页现有回归、小程序编译预检、`release:preflight` 和受控生产工作流的完整发布门禁。

网络故障时客户端恢复原显示，并查询服务端核对是否已经接受本次操作；快速连点保持单个在途请求，切换公告后丢弃旧公告的迟到响应。

可在后台立即关闭某条公告互动。代码回滚使用既有受控发布工作流部署上一份稳定 Git 提交；保留公告和独立回应存储，不需要修改课表 Release Pack。正式微信版需按微信平台审核/发布流程上线，上传体验版不能计作正式发布。
